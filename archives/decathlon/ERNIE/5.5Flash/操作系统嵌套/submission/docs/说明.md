# Nested OS 操作与格式说明

Nested OS 是一个 Windows 桌面应用（Electron 45 + Chromium + Three.js），实现可递归嵌套的图形操作系统。根系统由宿主直接实现；根系统之下，每个子系统都由父系统文件系统中的一份**内核程序**运行，窗口管理、文件管理器、播放器、图表与飞控也都是子系统里的程序。所有系统共享逐级拨付的执行预算、内存与存储配额。

## 1. 启动与目录

- 启动：`npm start`（根目录）。也可使用 `npm start -- --data-dir <目录> --width 1600 --height 1000 --remote-debugging-port=19106`。
- `--data-dir` 指定独立数据目录，运行数据只写入该目录，不写回源码目录。
- 本地静态服务固定使用 `18106` 端口；桌面调试端口默认 `19106`。
- 初次启动显示根系统桌面（`outer`），不自动播放演示。根桌面提供“新建子系统”图标与开始菜单入口。
- 非根实例按全局创建顺序命名为 `inner-1`、`inner-2`……；父子关系由系统树表达。
- 断网时所有本地应用、场景、程序与内核仍可运行；只有根系统浏览器需要真实网络。

## 2. 桌面与窗口

- 图标单击选中、双击打开；桌面与文件项支持右键菜单；文件列表支持 Ctrl/Shift 多选。
- 窗口：标题栏拖动、八向边缘缩放、双击标题栏最大化/恢复、最小化、最大化、关闭；拖到左右边缘可半屏贴靠。
- 任务栏左侧开始按钮与固定应用，中部运行窗口，右侧系统托盘、时钟与通知入口。
- 开始菜单可搜索并启动应用；`Esc` 关闭开始菜单、右键菜单与弹层。
- 每个实例有独立壁纸、图标、开始菜单、任务栏、窗口、焦点和通知。子系统桌面完整位于父系统的系统窗口中，逐级裁剪。
- 设置中的界面缩放使用 CSS `zoom` 作用于该层桌面，窗口坐标、命中与拖动均按缩放换算。

## 3. 递归系统树与生命周期

- 每个系统可创建直属子系统；子系统作为父系统里的承载进程运行，执行父系统文件系统中的内核程序。
- 支持至少四层桌面（根 + 三层子系统）；同一父系统可同时运行多个子系统。
- 每个实例有独立进程表、程序状态、虚拟时钟、消息队列、文件系统、桌面与应用状态。
- **暂停**：停止整棵子树的时钟、内核、进程、等待与应用推进；继续后后代保留各自暂停/挂起状态。
- **单步**：父系统可让暂停的直属子系统推进一个 20 ms 逻辑步（后代仍遵守各自暂停与速率）。
- **停止/关闭**：停止整棵子树；兄弟子树与祖先继续运行。关闭后快照仍可恢复。
- **重启**：结束子树进程，重新载入父系统中的内核源文件，按保留的系统树结构从初始运行状态重启，保留文件。
- **新建**：在系统管理器或桌面“新建子系统”中创建；可继续递归。

## 4. 程序语言 NOScript

程序是系统文件系统中的文本文件（扩展名 `.prog`）。语法示例：

```
# 注释
let x = 1
set x = x + 1
if x > 3 {
  call log("large")
} else {
  call log("small")
}
while x < 10 {
  set x = x + 1
  call sleep(100)
}
let pid = spawn("/Demo/receiver.prog", "receiver")
call send(pid, 42)
let m = recv(1000)
let s = file_read("/Documents/a.txt")
call file_write("/Documents/a.txt", s)
```

- 数据类型：数字、字符串、布尔、`nil`、数组（`[1,2,3]`、`a[0]`）。
- 运算符：`+ - * / % == != < > <= >= && || !`；字符串 `+` 拼接。
- 语句：`let`、`set`、`if/else`、`while`、`call`、`break`、`continue`。
- 注释：`#`、`//`、`/* */`。
- 变量、数组、字符串、消息都计入所属系统的内存配额；字符串拼接、数组复制、文件处理、表格重算、图表计算、飞行物理与显示提交都按规模计费。

### 系统服务（系统调用）

| 调用 | 说明 |
|---|---|
| `time()` | 读取本系统虚拟时间（秒） |
| `sleep(毫秒)` / `yield()` | 等待指定虚拟时长 / 让出本次执行 |
| `spawn(路径, 名称)` | 载入本系统程序并启动，返回 pid；失败返回 -1 |
| `kill(pid)` / `self()` | 结束进程 / 取得自身 pid |
| `send(pid, 值)` / `recv(超时)` | 发送消息 / 接收消息（-1 表示无消息） |
| `file_read(路径)` / `file_write(路径, 内容)` | 读写本系统文件 |
| `file_exists` / `file_list` / `file_delete` / `file_mkdir` | 文件操作 |
| `log(文本)` | 写入进程运行输出 |
| `rand()` / `rand(n)` | 本系统确定性随机数 |
| `wm_config(层叠, 焦点规则)` | 窗口管理程序下发层叠与焦点规则 |
| `files_config(排序)` | 文件管理器程序下发排序规则 |
| `player_tick()` | 播放器进程推进播放位置并提交画面 |
| `flight_tick()` | 飞行动力学进程推进机体状态 |
| `chart_handle(消息)` / `chart_tick()` | 图表进程接收数据版本 / 推进过渡 |
| `sensor(编号)` / `control(总距, 滚转, 俯仰, 偏航)` | 飞控传感器与舵面 |
| `set_quantum` / `set_priority` / `set_msg_limit` / `set_fs_rule` | 内核调度、消息与文件策略 |
| `service(名称, 值)` / `service_reply(请求号, 值)` | 自定义系统调用与内核回复 |
| `panel_clear` / `panel_rect` / `panel_text` | 向本系统显示设备提交二维图形 |

预置程序：`/Demo/add.prog`（累加）、`/Demo/loop.prog`（持续计算）、`/Demo/sender.prog` 与 `/Demo/receiver.prog`（消息）、`/Demo/service.prog`（自定义系统调用）、`/Demo/draw.prog`（二维显示）。

## 5. 内核程序

- 每个非根实例对应父系统文件系统中的 `/System/kernels/<实例>.kernel`（根系统模板为 `/System/kernel.sys`）。
- 内核程序是普通程序文件，由父系统承载进程执行，和普通程序一样消耗父系统预算并计入父系统读数。
- 内核决定：`quantum`（每进程每步连续执行的指令数）、`msg_limit`（消息队列上限）、`fs_prefix/fs_replace`（文件路径重写）、进程优先级，以及通过 `service` 提供的自定义系统调用。
- 修改方法：在父系统编辑器中打开 `/System/kernels/<实例>.kernel`，保存后在该子系统的任务管理器或系统管理器中“重新载入内核/重启”。其他子系统不受影响。
- 增加系统调用：在内核的 `recv` 循环中增加对 `m[0]` 的判断，用 `service_reply(m[2], 结果)` 回复。程序调用 `service("名称", 值)` 即可得到结果。
- 内核写坏（语法/运行时错误）时，该子系统显示“内核错误”并停止；父系统与兄弟系统照常运行；修正后可重新启动。

## 6. 飞控接口

排演中的飞控是 `/System/controller.prog`（可在编辑器查看/修改，也可在排演面板选择其他程序）。控制周期由程序的 `sleep(20)` 决定，实际执行受调度与预算限制。

传感器编号：

| 编号 | 含义 |
|---|---|
| 0 | 滚转角（度） |
| 1 | 俯仰角（度，机头下俯为正） |
| 2 | 离地高度（米） |
| 3 | 垂直速度（米/秒） |
| 4 | 航向（度） |
| 5 | 到目标停机坪的水平距离（米） |
| 6 | 目标方位（度） |
| 7 | 前向速度（米/秒） |
| 8 | 旋翼转速（0–1） |
| 9 | 是否接地（1/0） |
| 12/13/14 | 俯仰/滚转/偏航角速率（度/秒） |

控制量：`control(总距, 滚转舵, 俯仰舵, 偏航舵)`，范围分别约 0–1 与 -1–1。控制量保持到下一次写入；错过周期的控制不补发。预算降低会拉长控制周期，机体抖动、发散直至坠毁；及时恢复可以拉回。场景中有两个停机坪，默认飞控可悬停并降落在二号停机坪。

## 7. 预算、配额与计量

- 每个系统每个逻辑步有有限总执行预算（根系统默认 60000 工作单位/步）。内核、普通程序、文件/表格/图表/飞行动力学/显示提交与直属子系统承载进程共同竞争。
- 子系统实际可用预算 = 父系统拨付（父系统总预算 × 拨付比例），并受本系统配置限制。调高时间速率、增加实例、创建应用或投送不增加预算。
- 每个进程有步内额度（默认 1200，可调）；量子默认 420。多个可运行进程轮转取得执行机会；持续计算程序不主动让出也受调度限制。
- 工作按完成进度计费：预算不足时保留进度，取得额度后继续；文件、表格、图表、飞行动力学与显示提交按规模计费。
- 内存配额：变量、数组、字符串、消息队列、进程与应用缓存、场景资源占用；存储配额：文件内容。配额不足时分配/载入失败并给出可处理错误。
- 任务管理器显示总预算、实际拨付、各进程累计工作、步内工作/额度、内存、消息与错误；可挂起、继续、结束进程，调整总预算、内存/存储配额、进程额度与直属子系统拨付。
- 宿主实际绘制与 Chromium 网页执行不计入逻辑预算；应用计算与子系统窗口管理计入所属系统预算。

## 8. 三维场景资源

场景是独立的数据文件（`.scene`，JSON），不含宿主代码。格式要点：

```
{
  "format": "nos-scene",
  "version": 1,
  "name": "场景名称",
  "environment": { "skyTop": "#...", "skyBottom": "#...", "sun": [x,y,z], "fogNear": 130, "fogFar": 620 },
  "terrain": { "size": 640, "segments": 128, "seed": 24, "hills": 1.0 },
  "helicopter": { "body": "#7b3fe4", "accent": "#ffd23f", "number": "24", "rotorScale": 1, "tailScale": 1 },
  "pads": [{ "x": 0, "z": 0, "r": 11, "label": "H1" }],
  "buildings": [{ "type": "hangar", "x": -42, "z": 30, "w": 26, "d": 18, "h": 8 }],
  "timeline": {
    "duration": 15, "fps": 30,
    "keys": [
      { "t": 0, "pos": [0,1,0], "rot": [0,0,0], "rotor": 0.2, "damage": 0,
        "cam": [[18,8.5,22],[0,2.2,0]], "label": "停机坪" }
    ]
  }
}
```

- 播放器从本系统文件系统打开资源；更改资源并重新打开后，画面按实际文件内容变化。播放器和显示设备代码中没有这架直升机的固定模型。
- 最小场景（一个物体、一盏灯、一台相机）见 `/Demo/minimal.scene`：一个 `pads` 停机坪、低起伏 `terrain`、一盏环境光/平行光与一台 `cam`，`timeline` 至少一个关键帧。
- 地形高度函数由 `seed/hills` 与停机坪压平共同决定；飞行动力学使用同一高度函数，因此修改地形或障碍会改变接触与坠毁结果。
- 播放帧率 30 fps（资源 `timeline.fps`）；逐帧推进 1/30 秒。播放速率与系统时间速率共同生效。
- 组件变换、材质、镜头与时序均可在此文件中修改。

## 9. 工作簿格式

示例工作簿 `/Demo/sample.sheet`（JSON）：

```
{ "format": "nos-sheet", "version": 1, "name": "示例工作簿",
  "cells": { "A1": "项目", "B1": "数量", "C1": "单价", "D1": "小计",
             "A2": "项目 A", "B2": 24, "C2": 6, "D2": "=B2*C2" },
  "formats": { "A1": "bold", "D2": "money" },
  "colWidths": { "A": 140 } }
```

- 公式支持 `+ - * /`、括号、单元格引用、区域引用与 `SUM`（也支持 `MIN/MAX/AVERAGE`）。
- 修改、粘贴、撤销/重做并完成重算后发布新版本；除零、无效引用与循环依赖显示 `#DIV/0!`、`#REF!`、`#CYCLE!`。
- 未保存修改同样发布给图表；保存格式为上述 JSON，可重新打开并保留内容、公式与基本格式。
- 图表连接按工作簿文档身份与选区建立；数据以副本跨层传递，子系统保存自己的数据。

## 10. 排演记录

- 排演记录为 `.record`（JSON）：保存场景资源、初态、实际输入与实际发生的控制时序（每 20 ms 一个样本），以及时长与结果。
- 重新打开后可跳转到任意位置；回放通过从初态按记录控制时序确定性重算，结果不随当前预算变化。
- 从同一记录位置可“继续排演”，改变风、航向、故障、预算或飞控程序，保存后形成新的连续记录；原记录仍可打开。
- 排演与系统完整快照是两种不同的保存能力。

## 11. 实时数据连接与图表

- 在任意深度的图表工作台选择根系统已打开的工作簿、矩形区域、标签列与一个或多个数值列，建立实时连接。
- 初始取得完整选区；之后每次单元格/区域编辑、粘贴、撤销/重做并完成公式重算后发布新版本。图表看到的每个版本都是重算完成后的完整选区。
- 支持分组柱状图/折线图切换、标题、坐标轴、图例、数据值与悬停/选中反馈。
- 暂停子系统或祖先时，根表格仍可编辑；更新在范围外按序暂存，继续后按序处理。
- 可主动断开/重新连接；断开后保留最后图表；关闭源工作簿时保留已接收数据并提示。快照恢复/分叉后连接为“已恢复，待重新连接”，重新连接取得当前完整选区。

## 12. 跨层窗口投送

- 播放器与图表窗口都有“投送到祖先桌面”入口，可选择任一祖先（含跨过中间层直接到根）。
- 目标桌面创建独立可移动/缩放/贴靠/最小化的投送窗口；源窗口保留；每个源窗口至多一个投送窗口。
- 源应用、状态与计算始终属于源系统，工作逐级记入承载预算；目标桌面只承载外框、显示与输入转发。
- 三维场景的资源与逐次提交以副本交给目标，目标接收后绘制；图表二维图形在各视图中正确。
- 投送中的播放、进度、飞行输入、镜头拖动、三维点选、图表类型与数值输入经接口进入源应用消息队列，由源进程处理后提交新显示。
- 最小化源桌面/中间系统/源应用不停止源进程，投送继续；暂停源系统或祖先时应用内容冻结、控件禁用并提示原因；目标桌面外框仍可操作。
- 关闭投送只取消视图；关闭源窗口/结束源应用/停止源子树时投送结束并反馈。
- 投送外框归目标系统，应用内容与交互结果归源系统。

## 13. 快照、恢复与分叉

- 每层可为直属子系统创建快照，保存为父系统文件 `/Snapshots/<名称>.snap`。
- 快照包含：系统树结构、内核程序及运行位置、进程状态与变量、调度与未完成工作、虚拟时间、消息与计时等待、内存占用、文件、桌面与应用状态、随机状态；播放器/排演/图表状态、场景资源与相机也在其中。宿主图形对象不属于快照。
- 恢复到原实例或从中启动独立新子树（分叉）；分叉后各节点使用新实例身份，内部关系指向分叉内对应节点。
- 快照可导出到本机/从本机导入；作品重启后导入仍能恢复整棵子树。
- 根系统实时数据源不属于快照；图表恢复后使用缓存数据，连接为“已恢复，待重新连接”。

## 14. 根系统 Chromium 浏览器

- 使用 Electron `<webview>` 加载真实外部网页；支持多标签、地址/标题更新、前进/后退/刷新/停止、网页内新窗口在浏览器内部处理。
- 网页视图随自制窗口移动、缩放、裁剪和遮挡；最小化后不显示，恢复后回到正确位置。
- 关闭标签/浏览器或从任务管理器结束浏览器时释放网页视图，其他应用与子系统继续。
- 外部网页按真实时间与网络状态运行，不纳入自定义系统虚拟时间、共享资源与完整快照；网页不接触宿主文件系统、Node.js 或系统内部对象。
- 加载失败显示错误与重试；网络或页面限制导致的失败不属于程序错误。

## 15. 自动化与稳定标识

- 根目录 `automation.json` 记录启动命令、参数、主窗口标题与素材路径。
- 主桌面渲染上下文提供 `window.bench`：
  - `window.bench.version` = 1
  - `await window.bench.ready()`：桌面已呈现并可操作
  - `await window.bench.reset()`：关闭应用与全部子系统，恢复当前数据目录初态，重置实例编号
  - `await window.bench.inspect()`：返回 `systems / windows / browsers / players / charts / projections`
- 关键控件带 `data-testid`；窗口容器带 `data-window-id`、`data-app-id`、`data-system-id`；控件带所属 `data-system-id`（以及应用窗口的 `data-window-id`）。应用标识：`files/spreadsheet/widgets/editor/browser/tasks/settings/player/charts/projection`。
- 常用标识：桌面 `os-desktop`、`desktop-icon`；开始 `start-toggle`、`start-menu`、`launch-files` 等；窗口 `app-window`、`window-titlebar/minimize/maximize/close`、`taskbar-item`；文件 `files-path/list/item/nav`；表格 `sheet-grid/cell/formula`；设置 `settings-wallpaper/accent/scale`；小组件 `widgets-toggle`、`widget-timer-*`、`widget-note-*`；编辑器 `editor-text/save`；浏览器 `browser-*`；系统 `system-new/pause/resume/restart`、`kernel-open/error`；任务 `tasks-budget/grant/memory/storage`；播放器 `player-*`；图表 `chart-*`；投送 `window-project`、`project-target`；排演 `rehearsal-*`。

## 16. 边界与限制

- 本题只要求 PC 端鼠标/键盘操作，界面为简体中文。
- 操作系统采用自定义程序与设备模型，不实现硬件启动、CPU 指令集或完整通用操作系统。
- 外部网页的 Chromium 执行、宿主实际绘制与窗口合成不计入逻辑预算；应用计算、子系统窗口管理、飞行动力学、图表与显示提交计入所属系统预算。
- 图形上下文可能丢失；丢失后从系统状态恢复，程序与播放位置不受影响。多个三维视图同时存在时各自维护独立画布与状态。
- 主窗口被其他窗口完全遮挡时，作品仍通过定时器推进逻辑与绘制，不依赖 `requestAnimationFrame` 的可见性。
