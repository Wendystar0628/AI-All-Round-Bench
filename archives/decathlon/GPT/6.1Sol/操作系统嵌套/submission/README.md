# 栖境 NEST · Nested OS

Windows 桌面递归系统实验室。原创山谷壁纸、紫黄 24 号直升机与全部程序资源随源码交付。

## 启动

```powershell
npm install
npm start
```

已安装依赖时直接 `npm start`，也可双击根目录 `启动栖境.cmd`。启动会先构建本地资源，不需要网络服务器。Electron 45.2.1。

```powershell
npm start -- --data-dir "$env:TEMP\nest-review" --width 1600 --height 1000 --remote-debugging-port=19106
```

默认数据保存在系统临时目录 `nest-os-data`，运行状态不写回源目录。`--data-dir` 可隔离不同测试。首次启动仅显示根桌面，不自动播放。窗口支持最高 3840×2160。

## 操作

- 双击桌面图标；开始菜单可搜索全部应用。桌面右键有快捷入口。
- 右上角「新建子系统」或系统树创建递归桌面。系统树可暂停、继续、单步、调速、重启、停止、快照、恢复、分叉。
- 子系统播放器、图表标题栏的「投送」可选择任一祖先。关闭投送仅取消视图。
- 根表格打开 `/Demo/sample.sheet`。在子系统图表选择这个已打开工作簿，填写 `A1:D4`、`A`、`D`，连接后修改表格即可实时更新。
- 在各层文件管理器之间拖文件会取得独立副本，支持祖先、后代和兄弟之间传递。底部支持本机导入、导出。
- 播放器默认 15 秒演出。底部展开飞行控制台，可开始排演、调风、改航向、触发故障、查看飞控或保存记录。
- 根桌面「使用指南」和各层开始菜单中的使用指南包含程序语法、内核修改、服务接口、资源格式、预算边界和快照说明。

## 源码结构与模型边界

`src/runtime.cjs` 是可序列化的指令执行器及设备服务。`fixtures/*.nest.json` 是预置程序，复制进各实例虚拟文件系统。子系统承载执行父文件系统内的内核指令，内核循环显式列举任务、逐个拨付时间片。指令、进程、程序计数器、变量、等待、消息及分段工作均进入快照。没有用系统名称判断固定程序结果。

Nest-1 使用 JSON 指令，不执行程序提供的宿主 JavaScript。调度策略在内核文件中；合成器和应用文件的策略及调用顺序可修改。窗口管理器负责焦点、层叠和输入路由；文件程序处理导航与文件操作，图表程序循环变换数据并提交数值，播放器程序推进时序，physics.nest 执行固定步长的飞行积分。这是一套实验性的自定义设备模型，不是完整通用操作系统。编译器的 JSON 语法解析为固定设备原语，编译服务程序可编辑，后续启动程序会先创建受预算约束的编译进程。编译器能编译自身，也可通过 `policy.aliases` 和结果变换修改编译规则。

逻辑步为 0.1 秒，普通指令最少 1 unit，数据复制按每 64 字节额外工作分段付费；未付完时保留指令债务和 PC，不提前提交结果。内核递归执行扣除共享剩余额度，预算和拨付按逻辑步累计封顶。场景取样、图表计算和快照写入按资源规模建立可续行工作。宿主 React 排版、Three.js 光栅化和 Chromium 网页不计 VM 预算。默认充足预算可运行四层；内存、存储以及进程额度均在进程管理器中可查看和调整。

三维数据来自独立 `.scene` 文件：nodes 支持 box/sphere/cylinder/cone/ring/text/terrain；position、scale、rotation、color、材质参数、group、spin、breakAt 均为数据。tracks 是时间、位置和欧拉姿态，effects 是确定时刻采样的三维粒子。最小合法场景见 `/Demo/minimal.scene`。绘制器通用，不含直升机部件定义。多个视图共用一个 WebGL 渲染设备，再复制当前帧至各视图，避免上下文数量上限；虚拟状态仅由系统进程推进。

飞控服务：`flight.sensor` 返回位置、速度、姿态与上次控制时间；`flight.control` 写总距、滚转与俯仰控制，实际控制与输入历史按时刻保存供物理程序读取。预置闭环以 0.1 虚拟秒运行，控制保持到下次写入，错过周期不补发。排演保存状态帧及输入/控制记录为 `.replay`，重新打开可跳转回放。

## 验证

`npm test` 统一运行运行时、复核回归和可编辑程序三组共 32 项检查，覆盖算术依赖、循环错误、分层预算、时间暂停隔离、消息副本、内核错误隔离、快照续行、分叉、图表消息更新、编译器修改与自编译、编译错误、排演暂停跳转、跨会话快照身份隔离，以及改写内核时钟/唤醒、WM、播放器、文件、图表、物理与自定义 UI 的实际行为。

运行中的应用还可用 `node tests/gui-check.cjs` 和 `node tests/desktop-check.cjs` 做界面验证（会在当前测试数据目录 reset，连接 19106）；截图写入系统临时目录。完成 gui-check 后，可再运行 `node tests/full-playback.cjs` 验证 15 秒演出停在末帧。CDP 整桌面截图使用 `Page.captureScreenshot({captureBeyondViewport:false,fromSurface:true})`，避免越界截图临时扩展嵌入网页的绘制视口。

自动化入口与素材位置见 `automation.json`。浏览器网页是隔离的 Electron webview，脚本、表单及网络直接由 Chromium 执行。


## 修改程序与生成界面

- 父系统 `/System/inner-N.kernel.nest`：启动窗口管理器、取得本步时间、推进时钟、判断等待/消息唤醒、轮转执行。保存后在父系统重启目标。
- 子系统 `/System/wm.nest`：窗口层叠、焦点、输入路由、启动及关闭程序。可挂起此进程检验输入是否停止。
- `/Programs/files.nest`、`charts.nest`、`player.nest`：实际文件操作、数据变换和播放时序，保存并重新打开应用后生效。
- `/Programs/physics.nest`：0.025 秒的积分与接地规则；`flight.nest`：闭环控制器。在播放器中可重新载入飞控，也可运行新的飞控程序接管当前排演。
- `/Programs/counter.nest`：从编辑器运行，程序通过 `display.submit` 提交 text/rect/line/circle/button/input 数据，输入经 WM 回到程序收件箱。把 `add` 的 1 改为 7，重新运行后按钮每次实际增加 7；可以替换其他应用的程序源文件。

新增表达式：`get`、`min`、`max`、`sin`、`cos`、`endsWith`、`literal`。`put` 修改程序私有对象/数组。`model.get/set/pick` 访问自身应用状态；`input.next` 接收应用输入；窗口、文件和显示接口均通过 `call` 使用。程序不获得 DOM、Node 或宿主计时器。

`node tests/authoring-gui.cjs` 验证实际编辑、运行、点击自定义界面和飞行排演；`node tests/graphics-gui.cjs` 验证 18 个视图、一个 WebGL 设备、上下文恢复和资源释放。

完整逐项复核及仍保留的实现边界见 **复核清单.md**。
