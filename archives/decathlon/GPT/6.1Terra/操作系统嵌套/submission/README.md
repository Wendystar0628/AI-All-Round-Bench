# Nested OS · 操作说明

## 启动

在项目目录执行 `npm install`，随后执行 `npm start`。启动时可传入 `--data-dir`、`--width`、`--height` 和 Electron 的 `--remote-debugging-port`。例如 `npm start -- --width 1440 --height 900 --remote-debugging-port=19106`。应用数据保存在 Electron 的用户数据目录；`--data-dir` 可隔离不同运行数据。离线运行需要先完成依赖安装。桌面背景 `wallpaper.svg` 和三维模型均由项目绘制。

## 使用桌面

双击桌面图标打开应用，开始菜单也可启动；拖动标题栏移动窗口，右下角调整大小。任务栏可恢复最小化窗口。系统管理器可创建多级系统，暂停、继续、单步、重启和保存状态。父系统暂停时后代时钟和播放器停止；恢复时保留后代自己的状态。单步为 0.1 秒。

文件管理器中的 `/Demo` 有示例表格和场景，`/Programs` 有示例程序。右键文件可移到回收站；在回收站选择文件并点删除可恢复到原位置。文件列表支持 Ctrl 多选，可跨窗口复制、剪切和粘贴目录，也可以拖动文件复制。导入与导出适用于本项目使用的文本和 JSON 文件。编辑器支持打开、保存和运行程序。表格直接编辑单元格，支持 `+ - * /`、括号、引用及 `SUM(A1:B2)`。图表工作台可以选择已打开的根系统工作簿，设置矩形范围、标签列和数值列（多列用逗号分隔，例如 `B,D`），连接后选择分组柱状图或折线图，点击投送可在根桌面打开同步视图。播放器支持播放、暂停、跳转、逐帧、速率和投送。点击“开始排演”启用简化飞行模拟，可改变风和目标位置、触发故障，并保存 `.flight` 记录；在文件管理器重新打开记录后可回放，在选定时刻点击“开始排演”继续模拟。`/System/flight.os` 是飞控程序，修改并保存后在下一次排演启动；飞控以普通进程竞争预算，可以在任务管理器中挂起或结束。

## 程序实验

程序文件采用 JSON，`code` 为指令数组。打开 `/Programs/累加.os`、`持续计算.os`、`发送消息.os` 或 `接收消息.os` 可以查看并修改，然后在编辑器点击运行；任务管理器显示执行位置、指令数、消息、输出及错误，可以挂起、继续和结束。变量以 `$` 前缀引用，未赋值变量默认为 0。例如：

```json
{"name":"计数","code":[
  {"op":"set","to":"n","value":0},
  {"op":"add","to":"n","value":1},
  {"op":"lt","to":"again","a":"$n","b":10},
  {"op":"jumpIf","value":"$again","target":1},
  {"op":"log","value":"$n"},
  {"op":"end"}
]}
```

也可以用逐行文本程序。指令名不区分大小写，带空格的字符串使用双引号；跳转目标是从 0 开始的指令下标。例如：

```text
SET n 0
PLUS n 1
LT again $n 10
JUMPIF $again 1
LOG $n
END
```

`/System/compiler.os` 是可运行的编译器程序文档，`aliases` 可将新的指令名映射到现有操作；编辑保存后用于后续启动。运行它会读取自身、编译并写出 `/Documents/compiler-built.os`。转换步骤由内置 `compile` 系统服务执行，按输入字节数计费。

还支持 `sub`、`mul`、`div`、`eq`、`concat`、`jump`、`time`、`self`、`wait`（秒）、`send`（pid/value）、`receive`（to）、`read`（path/to）、`write`（path/value）、`spawn`（path/to）、`find`（name/to）、`kill`（pid）、`compile`（source/to）、`sensor`（key/to）、`actuate`（thrust/steer）、`accept`（value）和 `call`（name/value/to）。`spawn` 从本系统文件加载程序并返回进程号；结束目标时，其未读取的消息会被清理。消息按目标 PID 排队，无消息时接收进程等待。系统每 0.1 秒按预算执行指令，普通指令消耗一个逻辑单位；字符串、消息和文件读写按 UTF-8 字节规模分期计费，预算不足时保留进度，付费完成后才提交操作。同级子系统分享父系统剩余额度，进程轮流取得量子。Chromium 网页和宿主绘制不计入指令预算。

创建子系统时，其父系统的 `/System/inner-N.kernel` 保存内核程序。其 `code` 使用与普通程序相同的指令格式；承载过程执行到 `dispatch` 时，剩余拨付才交给子系统。内核自身指令会消耗父系统拨付，不执行 `dispatch` 的循环会使该子系统无法取得程序执行额度。通过系统管理器的“内核”打开并保存，重启子系统后生效。`quantum` 修改进程轮转量子，`policy` 可为 `round-robin` 或 `reverse`；`messagePrefix` 和 `filePrefix` 改变消息和文件规则。`calls` 可定义以 `value` 为输入的算术表达式，程序通过 `call` 使用。无效配置导致该子系统进入内核错误状态；修改文件后再次重启可恢复。状态保存包含已有子树的文件、时钟、程序状态、消息及常用应用窗口状态；图表恢复后需要重新连接。可从快照分叉，分叉使用新的系统编号；也可在文件管理器打开快照文件。

## 当前限制

这是可运行的实验原型，并未实现题面全部要求。系统窗口管理和应用仍由宿主代码实现，内核承载指令和调度参数可编辑，但系统调用分发、窗口管理和应用仍由宿主服务实现；编译转换也由宿主系统服务实现，完整工作量计量、包含应用窗口的完整快照和分叉重建尚未实现。场景文件是可编辑 JSON，描述节点几何、材质、灯光、镜头和关键帧；飞行控制及排演采用简化二维动力学。表格仅有基础公式与编辑，图表目前采用简化坐标与过渡；浏览器使用 Electron 的 Chromium webview。快照可重建部分已关闭的常用窗口，跨应用重启后可从文件打开为新分支；仍不能完整还原所有应用状态、跨界投送和数据连接。


## 子系统服务程序

每个子系统启动时从 `/System/window-manager.os`、`files-app.os`、`chart-app.os`、`player-app.os` 载入服务程序，作为普通进程竞争本系统预算。修改并保存后，通过父系统的“重启”重新载入。服务程序运行得到的变量参与界面行为：窗口服务通过消息确认窗口聚焦，`stack` 为 `back` 时，新聚焦窗口会置于后方；文件服务的 `order` 为 `descending` 时倒序列出文件，`writable` 为 `false` 时阻止文件管理器写入；图表服务的 `factor` 会乘以读取的数值；播放器服务的 `rateScale` 影响演出推进速度。每个文件、图表和播放器源窗口会载入独立服务进程；可在任务管理器挂起或结束，关闭窗口会释放其服务进程及待处理输入。服务暂停时对应应用不再处理受该程序管理的输入或更新。文件列表和应用按钮的输入会发送给对应服务进程，默认程序用 `receive` 取得事件，再以 `accept` 确认后执行；移除确认指令会阻止这些操作。输入需要取得预算后才响应。

这些服务程序目前控制的是列出的部分规则和按钮、文件项输入，文本编辑、拖动及其他交互仍由宿主处理；宿主也承担界面绘制、命中分发和大量应用逻辑，不能将其视为已实现完整的可编程窗口管理器或应用。

## 飞控接口与记录

排演启动时加载 `/System/flight.os` 并创建飞控进程。`sensor` 可读取所属飞机的 `time`、`x`、`y`、`vx`、`vy`、`angle`、`angularVelocity`、`wind`、`heading`、`fault`、`thrust` 和 `steer` 数值；`actuate` 写入 `thrust` 和 `steer`，控制量保持到下一次写入。推力限制在 0 至 20，转向限制在 -3 至 3。示例飞控通过普通计算指令计算控制量并等待下个周期，修改程序或挂起其进程会改变后续运动。排演记录包含采样状态及控制量，重新打开后可拖动时间，点击“开始排演”从当前记录位置续演。模型使用简化二维动力学，并未实现题面要求的完整三维障碍碰撞。

## 场景资源格式

场景是独立的 JSON 数据文件，默认资源为 `/Demo/helicopter-24.scene`。在编辑器中修改并保存，再从文件管理器打开即可看到变化。`nodes` 为树形节点；节点支持 `box`、`sphere`、`cylinder`、`cone`、`plane`、`ring` 和 `label`，并可设置 `position`、`rotation`、`scale`、`color`、`roughness` 和 `children`。`role` 为 `actor`、`rotor` 或 `tailRotor` 的节点接收时间轴姿态。`animation.actor` 保存时间、位置和角度关键帧，旋翼速度使用 `rotorSpeed` 和 `tailRotorSpeed`。例如：

```json
{"version":1,"name":"单物体","duration":3,"background":"#35455d",
 "camera":{"position":[6,5,10],"fov":40},
 "lights":{"sky":"#ffffff","ground":"#555555","sun":"#ffffff","sunPosition":[8,20,12]},
 "nodes":[{"name":"方块","shape":"box","color":"#ed8050",
           "scale":[3,3,3],"position":[0,2,0],"role":"actor"}],
 "animation":{"actor":[{"time":0,"position":[0,2,0],"rotation":0},
                        {"time":3,"position":[3,2,0],"rotation":0}]}}
```

图表更新由数据接收和绘图计算两个工作阶段处理，可在任务管理器分别挂起；暂停源系统时投送外框仍可操作，图表内容和控件会冻结。数据复制和绘图工作的逻辑费用按选区值的字符规模计算，预算不足时保留进度。每个系统的任务管理器可设置指令预算、程序内存和文件存储的字节限额；小组件的倒计时和秒表在关闭面板后继续运行，通知与设置共享免打扰状态。内存按程序和消息序列化大小估算，存储按文件路径及内容的 UTF-8 字节数计算。内存和存储检查逐级包含后代，兄弟实例共同占用祖先额度；当前内存估算包含程序、消息、播放器和图表数据，不覆盖所有 DOM、图形驱动对象及 Chromium 网页。
