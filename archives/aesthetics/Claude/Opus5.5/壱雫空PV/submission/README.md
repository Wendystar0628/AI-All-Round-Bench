# 壱雫空 — MyGO!!!!! ｜ 网页 PV

在浏览器里实时渲染的平面设计风格 PV，对应歌曲前半首（81.4 秒，36 个镜头）。

## 打开与操作

- 在 Chrome 里直接双击 `index.html`，不需要服务器。素材预热约 1 秒，之后点击画面开始播放（浏览器要求播放声音前先有一次点击）。
- 底部居中悬浮一条胶囊式控制条，有播放 / 暂停、可拖动的进度条（悬停时显示时间和镜头号）、当前镜头号和镜头名，以及全屏按钮。它只占画面下沿中段，不盖住 PV 左下的时间码和右下的小节读数。窗口比 16:9 更高时，它落在下方黑边里。播放中鼠标静止约 2 秒，或移出窗口，控制条就会隐藏；暂停时一直显示。
- 实测播放时，画面所用时间与音频时钟平均相差约 4 毫秒，最大 12 毫秒，不到 60 fps 下的一帧。
- 快捷键：`Space` 播放 / 暂停，`←` / `→` 后退 / 前进 3 秒，`Home` 回到开头。
- 画面始终保持 16:9，窗口比例不同时加黑边居中。

## 实现方式

| 部分 | 做法 |
|---|---|
| 平面画面 | Canvas 2D。所有色块、线条、文字、纹样都由代码实时绘制，统一在 1920×1080 的逻辑坐标里，再按实际像素缩放，4K 下同样清晰 |
| 三维板块空间（镜头 23–27、34、35） | 自写的 WebGL2 小渲染器：板块是平涂贴图加描边，立体字用多层切片堆出厚度，再用线性雾融进深墨蓝；渲染结果合成回 2D 画布 |
| 3D 半透明伞（镜头 06、14、20、31） | `js/umbrella.js`，同一个 WebGL2 上下文里的真实网格模型，详见下面“3D 半透明伞”一节 |
| 时间 | 每一帧都只由歌曲时间 `t` 决定，各类“随机”都用种子哈希生成，没有逐帧累积的状态。拖动到任意时刻，看到的就是那一刻的画面 |
| 与音频同步 | 以 `<audio>` 的 `currentTime` 为时钟，两次更新之间做平滑外推 |
| 图像 | 画面中的图像只用题目给的五张立绘。`_dev/build_assets.py` 把它们去背、裁边，并另外烘焙一版白描边贴纸，以 WebP data URI 形式写进 `assets/data.js`。这样以本地文件方式打开时，WebGL 贴图和像素读取都不受限制 |
| 字体 | 全部用本机字体：明朝体 Source Han Serif（歌词主字体）、Yu Gothic（和声，横向压窄并拉开字距）、Montserrat（装饰英文）、Anton（巨字）、Playfair Display（SOYO 细衬线）、JetBrains Mono（时间码）。每一项都配了后备字体。本机的 Source Han Serif 是中文区域版本（“源ノ明朝”也是它的别名），我把歌词里可能存在中日字形差异的字（今、消、溢、遮、込等）和日文明朝 MS P明朝 逐个对照过，字形结构一致；直、骨、角这类字形不同的字歌词里没有 |
| 质感 | 平涂为主，全片叠一层很细的颗粒，颗粒按 24fps 换帧 |

文件结构：

```
index.html          播放页（画布、开始页、控制条）
assets/data.js      立绘（原版 + 白描边贴纸）与音频响度包络
assets/hitoshizuku.mp3
js/core.js          节拍网格、缓动、随机哈希、配色、立绘工具、通用图形
js/lyrics.js        21 句歌词的逐字时间与“跟唱”渲染
js/gl3d.js          WebGL2 板块渲染器
js/umbrella.js      3D 半透明伞：建模、透明塑料着色、雨滴
js/overlay.js       常驻版面层、跑马字、颗粒、跨镜头字幕
js/shots1-4.js      36 个镜头
js/main.js          播放器、控制条、videoExport 接口
_dev/               开发用脚本（音频分析、素材生成、本地服务器），运行作品不需要
```

## 3D 半透明伞

凡是出现伞的镜头（06、14、20、31），伞都是建模出来的立体物件，合成进平面画面；伞周围的元素仍是平面的。

- **模型**：一把透明塑料伞。8 根伞骨从伞顶弯成穹顶；8 片伞面在相邻伞骨之间绷平，伞骨处形成折线，伞沿在两根伞骨之间收成扇贝形。另有撑杆、伞巢、中棒、伞顶帽和伞尖、伞骨末端的珠头、J 形手柄。模型按张开程度生成并缓存，所以伞可以弹开、收拢。
- **伞面质感**：伞面着色器读取已经画好的 2D 画面作为背景，按伞面法线把它轻微错位，形成折射。每片伞面的错位不同，背景的条纹到了折线处会断开。代表色用乘法淡淡染在伞面上，并散射出一点同色的光，仍然透光。折线、伞沿的包边和掠射角处提亮。受光一侧有高光（光源有位置，所以平的伞面上是一块会衰减的反光，而不是整片发白），每片朝光的伞面上还有一道柔和的光带，伞转动时光带跟着走。
- **两层伞面**：先画实心部件和远侧伞面，再把帧缓冲拷贝一份，然后画近侧伞面，并让它折射这份拷贝。所以隔着近侧伞面，看得见伞骨、撑杆和远侧伞面，颜色叠两层更深一点。
- **雨滴**：2D 画的水珠，位置取伞面上的点投影到屏幕。水珠按伞面朝向压扁，高光朝向光源。朝镜头的水珠画在伞上面；背向镜头的先画，再被伞面透过来（镜头 14 从伞下往上看，伞面上的雨滴都是透过伞面看到的）。几种雨滴：散落的静止水珠（大小不一）；会滑的水珠（停一会儿 → 沿伞面加速滑到伞骨末端，身后拖一串细小的水痕 → 在伞骨末端聚住、变大 → 滴落）；挂在伞骨末端、慢慢长大再落下的水珠。全部只由时间决定。
- **各镜头**：
  - 06：一把小伞斜靠在封套的片名右上方，缓慢自转，在封套上投下柔和的影子，伞面干净，没有雨滴。
  - 14：一把很大的伞，向远处倾斜，镜头从伞下往上看进伞里：伞面占画面上半，伞骨从伞心放射出去，伞柄从伞心垂向画面下沿；透过伞面看见后面的横条纹（第 23 小节换成竖条纹）。伞在第 22 小节第 1 拍弹开（伞面略微冲过全开再回位），之后缓慢自转，伞面上的光带、透出的条纹和雨滴跟着转。会滑的水珠只选在画面里看得见的那半边伞面上，整场有几颗完整地滑落、聚住、滴下。第六句沿伞沿下方的弧线排开，以伞柄为中线，伞柄正好从两个字之间穿过。
  - 20：五把伞各染一点代表色，每把身后垫一团同色柔光，透过伞面看，伞就在深底上透着光。伞每拍从右侧滑入一把：滑动时向前倾，停下时回摆一下；伞面上的水珠滑动时向后滞，停下时颤一下；刹住的那一刻，前沿甩出三颗水珠，带着伞的惯性飞出再落下。第 34 小节换成正俯视（视距拉远，透视更平）：五把伞是五个透光的圆，压在白色条纹上，伞面上的水珠滑到伞沿后离开。
  - 31：五把带代表色的伞从正上方看，围成一朵五瓣花，同步缓慢转动，保持五瓣对称；代表色同时画在伞沿包边和折线上，在晴空蓝上也认得出是谁的伞。伞面上留着五颗左右被阳光照亮、会闪的水珠。伞在拍前一瞬收拢，伞面朝画面里合起，同一位置弹出圆框。彩色伞面在天空上投下带颜色的淡影。

## 跟唱时间轴

LRC 只给了每句的开始时间。我用 Chrome 把音轨解码成 PCM，用 Python 提取中置声道的谐波成分，再算基频显著度，画成钢琴卷帘图（`_dev/pitchview.py`、`_dev/pitchplot.py`、`_dev/overlay2.py`）。然后对照 21 句歌词的读音和音拍，逐个定出每个字（音节）的起唱时间，写在 `js/lyrics.js` 里。

定稿后又做了一次校验：从页面导出 `js/lyrics.js` 实际使用的逐字时间，叠回 21 句的音高图（`_dev/checklyr.py`），逐句对照音符起点。第三、六、八、十、十四、十八句有个别字偏差 0.1–0.35 秒，已改正。第八句的“こぼれ落ちる／音響いて”正好对应前后各 6 个音符，改正后每个字都落在自己的音符上。第五、九、十二句和声在中置声道里分辨不出，按句内均匀分布处理。

## 对拍

全片的拍点都按题面公式计算：204 BPM，第一拍在 0.045 秒，每拍 60/204 秒。为确认这套网格与录音吻合，我用 `_dev/beatcheck.py` 从音轨检测起音，逐拍对照：277 拍中有 269 拍在 ±70 毫秒内找到对应的鼓点或起音；每 8 小节的中位偏差从开头到结尾都稳定在 +20 到 +45 毫秒，说明速度没有漂移。题面点名的重音也吻合：35.39 秒实测在 35.396 秒，59.78 秒在 59.796 秒，79.60 秒在 79.641 秒。剩下约 30 毫秒的整体偏差不到两帧，可能来自检测方法本身，所以网格保持题面给出的数值。

题面第 4.9 节要求“动作稍早于拍起步，在拍上到位、定住”。带回弹的入场动画在时长的 40–45% 处才第一次到达目标，所以凡是踩拍的回弹动作，起步时间都按曲线反推：让这第一次到位正好落在拍上，预备动作相应提前。逐项核对后的误差：
- 镜头 04 第 6、7 小节版面切换：不超过 0.02 秒；
- 镜头 12 卡片按八分音符落下：落在八分音符上；
- 镜头 15 圆环逐拍出现、镜头 30 贴纸与三张卡片、镜头 33 巨字挪格、镜头 34 五色环：都在拍点 ±0.01 秒内；
- 镜头 31 伞收拢、圆框弹出：在第 56 小节第 2–4 拍和第 57 小节第 1–2 拍后约 0.03 秒。

镜头 04 由一个圆分成三个圆时，三个圆从原来那个圆的位置和大小出发，半身裁切在最上层，所以分裂开始那一刻与单圆画面完全一致。

## 跟唱规则

- 一句开唱前，整句先以空心描边占位；
- 唱到哪个字，那个字由上往下（竖排）或由左往右（横排）填实；
- 任何时刻只有正在唱的那个词用强调色（天蓝 / 阳光黄）标出，唱完淡回本色。

## 主动扩张（分镜之外自己加的内容）

1. **逐音节跟唱和跨镜头字幕**：每个字落在它自己的音节上，而不是整句均分；正在唱的词才是热点（例如镜头 03 词下的天蓝下划线，镜头 33 巨字下的阳光黄条）。有几句歌词会越过镜头边界：句尾拖进下一个镜头，或下一句提前弱起。这时版面层下方会临时浮出一条小字幕，保证每个唱出的字都看得到。
2. **预副歌的“点亮”指示器（镜头 24–26 右上角）**：五个小圆点按分镜的点亮顺序逐小节亮起，依次是鲜绿、珊瑚粉、橙黄、靛紫、天蓝，亮起时弹一下。把“代表色一种一种亮起来”这条线索做成界面元素。
3. **常驻版面层的音乐读数**：右下角实时显示小节号和拍号；时间码前的红点按拍闪烁；画面上下边中点加了套准十字；开场英文小字逐字打出时带块状光标；进入第 51 小节的静默时，时间码停住。版面层文字都带一圈反色细描边和柔光，所以压在立绘、条纹或天空上都能看清；落在浅色背景上时，描边与背景融在一起，看不出来。前奏的小节拍器点亮时，是一个实心方块，中间嵌着当前成员的代表色，即使压在同色底上（如爽世的橙黄）也看得见。
4. **排印上的补充层**：歌词说明条（■ LYRIC 04 —— 0:18.86）、罗马字注音（WASUREZU NI / ARUITEKU YO 等）、镜头 04 给“ひとしずく”加的小号“一滴”注释，以及卡片上的编号、条码和刻度。这些贯穿全片，作为统一的版式细节。
5. **镜头 33 的拍立得**：加载时实时重绘 03、06、08、12、15、20、24、29 号镜头作为缩略图，所以卡片里就是这支 PV 自己的画面。
6. **首尾呼应的纸条**：镜头 01–02 右侧的纸条里竖排着第一句歌词。到镜头 36，构图回到镜头 02（同一个撞击点、同一根引导竖线、左侧斜线纹、下部跑马字带），同一位置的纸条里换成最后一句“僕はあつめたいよ ああ ひとしずくを”。
7. **伞的“表演”**：分镜只规定了伞的样子和雨滴的聚、滑、落，我又给伞加了跟拍的动作和物理细节：镜头 14 的伞在下拍上弹开，伞面冲过全开再回位；镜头 20 的伞滑入时前倾，刹住时回摆，水珠先向后滞、再颤，前沿甩出的水珠带着惯性；滑动的水珠身后拖一串细水痕；镜头 31 的彩色伞面在天空上投下带颜色的淡影，残留的水珠在阳光下轮流闪光。

## 与分镜不同的处理

分镜要求的时间点、元素和动作都做了。以下几处因为实际演唱时间、画面可读性或版面冲突而做了调整：

- **“一滴”**：LRC 里这个词写作平假名“ひとしずく”，画面用歌词原文。实际演唱中这个词在第 7 小节唱完（7.13–8.0 秒），所以第 7 小节先跟唱填色；第 8 小节第 1 拍按分镜把它放大到画面中央，用天蓝色，其余文字缩到右侧。副歌镜头 34 同样按实际演唱时间（78.2 秒起）把它变成实心阳光黄。
- **镜头 05**：分镜没写文字，但第三句后半“顔上げた今日の僕を”正在唱，所以把它沿横线放在圆内跟唱，前半句作为小字注在线下。最后一拍两条跑马字带停住，但保持可见；镜头 06 从中央那个点长出，扩大的圆盖过停住的色带。
- **镜头 06**：五个感叹号的落下时间提早到第 4 拍的 0.12 拍处。原定第 4 拍后半拍落下时，正好被前奏的签名色幕盖住，提早后才看得见。
- **镜头 07**：乐奈的上半身放大到约 2.5 倍画面高，大半在框外，脸留在画内。RANA 巨字只有绿色描边，外面垫一圈白边，与身后的竖条纹分开。
- **镜头 10**：底鼓圆窗里的彩色局部改为“举起的鼓棒、手和镲片”。立希两只手之间正好是脸，同时包住双手的圆形裁切必然会放大半张脸，与“不做脸部特写”冲突。第 3 拍圆窗扩满全屏时，整张彩色立绘照常显现。
- **镜头 12**：转盘左移一格后，灯的卡片不在正中。第 19 小节放大时，她的卡片一边放大一边移到中央。
- **镜头 13**：和声分写在四块磨砂面板底部的透明标签区。未唱时字在磨砂后面是模糊的，唱到时变清晰。这样字不会和剪影叠在一起难以辨认。
- **镜头 15**：第七句沿最外圈排成一个完整的圆环；一句字数不够绕满一圈，所以写了两遍，随圆环一起转。
- **镜头 16**：黑白棋盘格色带放在谱线的上下两侧，像胶片齿孔，让写在谱线上的歌词保持清楚；两个取景框做成 CAM A / CAM B 两路机位，录制中的那一路亮起。播放器卡片里我加了一张小封套，但不画伞：题面规定伞只出现在镜头 06、14、20、31。
- **镜头 17**：立希的鼓棒做成带白边的剪贴卡，避免立绘裁切处出现生硬的直边。
- **镜头 18**：第十句实际 34.56 秒才开唱。第 29 小节先让空心占位字逐字出现，填实则跟随实际演唱。左半边的半调网点缓慢斜向流动，满足主歌“每个版面里都有持续的小动作”。
- **镜头 19**：第十句在这一小节还在唱，所以把它放在横线上方，用白色小字继续跟唱。最后一拍竖缝正好在第 32 小节第 1 拍完全拉开。
- **镜头 20**：第 32 小节只有四拍，所以前四把伞落在第 32 小节的四个拍上，第五把落在第 33 小节第 1 拍，正好与“画面整体上移”同时开始。
- **镜头 20–22**：第十一句句尾“いこう”拖进镜头 21，保留在天空区域。和声（41.87–46.2 秒）横跨 21、22、23 三个镜头，处理如下：
  - 镜头 21 把第一段“アスファルト染めていく”像路面标线一样写在透视地面上；这块地面用 WebGL 渲染，以得到真实的透视压扁；
  - 镜头 22 让整句和声绕成圆环，围在圆框外；
  - 镜头 23 拉开后，下方字幕把这句和声唱完。
- **镜头 22**：选的成员是爽世，代表色为橙黄。

## 视频导出接口

```js
window.videoExport.runs                         // ['pv']
await window.videoExport.begin('pv', { fps })   // 回到开头，隐藏控制条，返回 { frames: ceil(音轨时长 × fps) }
await window.videoExport.frame(i)               // 第 i 帧 = 音轨 i / fps 秒；返回时画面已绘制完成
window.videoExport.end()                        // 回到普通播放页
```

- 进入导出模式后，音频暂停，画面只由 `frame(i)` 推进。
- 画布按窗口实际像素重建，最高 3840×2160。
- 3 fps 时共 245 帧，60 fps 时共 4884 帧。
- 以本地文件方式打开时，接口同样可用。
