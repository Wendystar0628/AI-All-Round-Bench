# 观测者票选

审美全能网站新增投票功能。观测者可以给每一卷里已经交卷的作品投票：每一卷最多两票，投给两件不同的作品。投过的那一卷会揭晓本卷的观测者排名；另有一个「观测者票选」页，统计每位设计师在各卷的得票和总得票。

本文是这项功能的设计：定位、规则、页面、交互、数据、服务端、防刷、部署和代码组织。网站其余部分的约定见 [design.md](design.md) 和 [data.md](data.md)。

## 一、定位

网站原本的立场是「只欣赏，不评判」：页面上不写分数和名次，型号按登记顺序排。加入投票之后，这一条改成：

- **测评本身仍不打分。** 评委只写点评；作品按参测登记的顺序陈列，题目页的页签、型号页、卷目页的顺序都不变。
- **名次只来自观测者，只出现在两处。** 一处是题目页的「本卷票选」，一处是「观测者票选」页。别的页面最多写一句「观测者 N 票」，不写名次。
- **说法统一叫「观测票」「观测者票选」**，不叫「评分」「排行」「打榜」。设计师仍称设计师。

功能上线时，`design.md` 要跟着改这几处：
- 第一节「只欣赏，不评判」那一段；
- 首页轨道里那句「同一份题面，交到每个模型手里，各自作答。灯已点亮，请入座。」要加上观测者的那一份（新句子待定，见第十四节）；
- 第六节末尾「不做：……投票……」；
- 第 9.2 节「不写分数、名次」；
- 页头导航四项改为五项。

## 二、规则

- **能投什么**：每一卷里作答已结束（`works.json` 里 `state` 为 `done`）、已经公开、并且网站上挂出了图的作品。正在作答（`answering`）、还没公开或还没有图的作品没有投票按钮，服务端也不收它的票。
- **每卷两票**：同一位观测者在同一卷最多投两票，必须投给两件不同的作品，同一件作品只能投一票。十卷各自独立，一个人最多投二十票。
- **可以撤回**：投出的票随时可以撤回，撤回后这一票回到手里，可以改投别的作品。
- **不设截止**：票选一直开着，排名随投票实时变化，页面上写明「截至几点几分」。
- **「一个人」怎么认**：一个浏览器算一位观测者（见第八节）。不登录，也不做验证码。
- **暂停公示时**（`topic.notice` 打开）：页面上没有作品，投票的部件一律不出现，票选页只写那句公示。

## 三、题目页：观测票和本卷票选

题目页下半部分是作品区：一排设计师页签，选中哪位就显示哪位的作品。投票嵌进这块作品区，不另开页面。

### 3.1 观测票

作品区页签那一排的右端，停着一张属于这位观测者、属于这一卷的纸票，叫**观测票**。

- **样子**：和观测卡、取件票是一家。
  - 纸面用同一张纸纹，带接触阴影；
  - 票面是微型印刷：AUDIENCE · BALLOT、本卷编号（No. 01/10）、一行 TWO PUNCHES PER VOLUME；
  - 票根是这一卷世界色最深的一档，写「投票」。
- **两个孔位**：票面上印着两个空的孔位，是一圈细印的虚圆。
  - 投出一票，就在一个孔位上打穿一个孔：孔里露出后面的夜墙，孔边一圈黄铜环，孔下用这一卷的墨盖印那位设计师的简称。
  - 两孔按投票的先后排列。
- **读法**：一眼能看出这一卷还剩几票、投给了谁。读屏读作「本卷观测票：已投 Claude Opus 5.5，还剩一票」。

### 3.2 投票按钮

每位设计师的作品区里，下载用的取件票旁边有一个投票按钮，叫**打孔钮**。

- **样子**：一枚小的黄铜打孔器形状，旁边写「投这一件」。它属于票这一家的部件，不做成通用按钮。
- **三种状态**：
  - 可投：常态。
  - 已投：打孔器旁边有一个打穿的小孔，字改成「已投 · 撤回」。
  - 票已用完：这一卷的两孔都用掉、这件又不是你投的。按钮压暗，字改成「两孔已用」，悬停时提示「撤回一票就能改投」。
- **页签上的痕迹**：你投过的设计师，页签小图版的右上角有一个打穿的小孔。切页签时不用打开也知道投过谁。
- **撤回**：两处都能撤回，结果相同。
  - 点作品区里的「已投 · 撤回」；
  - 或点观测票上那个孔。孔上先贴一片小纸补丁，补丁淡出，孔位回到印着的虚圆。

### 3.3 本卷票选

页签那一排上方是**本卷票选**（英文 VOTES · THIS VOLUME）。

- **投票之前**：这里只放一张折起来的纸签，写「投下一票后揭晓本卷排名」，下面一行小字「已有 N 位观测者投票」。
- **投出第一票后**：纸签展开成星表，排版像一页印出来的天文星表。每行依次是：
  - 名次：Didone 斜体数字；
  - 设计师名：二等名字的排法；
  - 票数条：一根 1px 黄铜细线上的实心段，长度按本卷最高票的比例；
  - 票数和占比：Didone 数字。
- **颜色**：只有第一名那一段用这一卷的点亮色，守住「一屏只有一处饱和」。其余是黄铜。
- **并列**：票数相同的名次相同，按登记顺序排在一起。没有票的作品也列出，票数写 0。
- **变化**：票数刷新时，各行用 `land` 曲线换位，数字直接换。
- **联动**：点星表里的一行，就选中那位设计师的页签。
- 撤回到这一卷一票都没有时，星表保持展开。揭晓过就不再收起；揭晓记在本地，下次来仍是展开的。

## 四、「观测者票选」页 `votes/`

新加一页，网址 `votes/`，英文 `en/votes/`。页头导航改为五项：I 卷目 VOLUMES、II 设计师 DESIGNERS、III 评委 JUDGES、**IV 票选 VOTES**、V 观测须知 NOTES，最右仍是 GitHub 和「中 / EN」。导航和页面标题的字都在 `src/i18n/*/common.json`、`votes.json`，要改只改那里。

这一页是母版的夜，一盏吊星。自上而下：

### 4.1 页首

- **标题**：「观测者票选」（英文 Observers’ Votes），展示字 900，「票」字放大，带一颗星芒。
- **背景字**：身后压一行斜体幽灵字 *the audience, under one lamp*，只比墙亮一点。
- **说明**：一句话说明，写给观测者看：每一卷两票、可以撤回、名次只来自观测者。
- **数目**：下面一行演职员表式的小字，依次是总票数、投票的观测者数、截至时间。

### 4.2 总得票

- **一行一位设计师**，按总票数从高到低排。每行依次是：
  - 名次：Didone 斜体；
  - 设计师名：二等名字，推理强度坐在帽线上；
  - 一根横条，后面跟总票数。
- **横条按卷分段**：每一段是那一卷的布色（世界色），段长是那一卷的得票。一眼能看出这位的票来自哪几卷。
- **悬停或聚焦一段**：浮出一张小纸签，写卷号、迷你锁定和这一卷的票数。
- **链接**：点设计师名进她的型号页。

### 4.3 星表

总得票下面是一张纸面的总表，排版像一页天文星表，叫**星表**。

- **结构**：
  - 列头：十卷，依次是卷号（Didone）、简称和迷你锁定（纸上的墨色形态）；
  - 行头：设计师，顺序和总得票一致；
  - 最右一列是总票，最下一行是每卷的合计。
- **每一格**写票数，旁边一个星点，星点大小按这一格在本卷的得票占比。
  - 每一卷票最高的那一格，星点换成这一卷的点亮色，极小。十颗各带一点自己的颜色，是首页十卷星座的同一种做法。
  - 其余星点是黄铜。
- **空格**：这位设计师没做的那一卷，格子里盖一枚很小的网点云遮印；做了但没票的写 0。
- **链接**：点列头进那一卷的题目页，并直接落在本卷票选；点行头进型号页。

### 4.4 窄屏

- 小于 960：星表在自己的框里横向滚动，第一列（设计师名）固定。整页不出现横向滚动。
- 小于 760：星表改成一位设计师一张纸卡，卡上十根小横条，一卷一根。总得票照常。

## 五、型号页

- **每一卷那一段**：在取件票旁边加一行小字「观测者 N 票」，不写名次，链到票选页。
- **页首**：演职员表那一行加一项「观测票 N」。
- 名字下面仍不放星。

## 六、状态与退路

| 情况 | 怎么画 |
|---|---|
| 没有脚本 | 页面是构建时画好的静态 HTML，投票部件默认隐藏，其余照常。票选页显示发布时的票数快照（第九节），写「截至发布时」 |
| 票箱连不上 | 观测票和打孔钮压暗，写「票箱暂时关着」。本卷票选和票选页退回发布时的快照，并注明 |
| 投票被限频 | 打孔钮旁边一行小字「投得太快了，稍等一下再试」，不弹窗 |
| 这件作品不能投（刚撤下、正在重测） | 不出现打孔钮；之前投给它的票不计入显示 |
| 这一卷还没有作品 | 不出现观测票和本卷票选，作品区照旧画云遮的夜窗 |
| 全站还没有人投票 | 票选页写「还没有观测者投票。」，星表只画表头 |

## 七、交互与动效

- **键盘与读屏**：打孔钮是真的 `<button>`，带 `aria-pressed`；观测票上的孔也是按钮，读作「撤回给某某的一票」。每次投票或撤回后，`aria-live` 区域读一句「已为某某投票，本卷还剩一票」。焦点框照全站的 2px 锈橙。
- **动效**（守设计系统第十节「先空一下，再一下子出来，然后久久不动」）：
  - **打孔**：孔位一下子打穿，黄铜环用 `land` 曲线描完一圈；打下的小圆纸片沿 `exit` 曲线往下落，随即淡出。
  - **撤回**：纸补丁用 `land` 贴上，停一下再淡出。
  - **本卷票选**：第一次揭晓时，纸签展开，各行从上到下依次落定。
  - **减少动态效果**：只剩 0.15 秒的透明度变化。
- **乐观更新**：点下去先在页面上把孔打出来，同时发请求。服务端拒绝时，孔用补丁动画退回，并写明原因。
- **刷新**：进入页面时取一次票数，投票或撤回后取一次。页面停在前台时每分钟取一次，后台不取。

## 八、防刷（不用验证码）

一个浏览器算一位观测者。下面四层叠在一起，能挡住随手刷票和脚本的高频请求，但挡不住有人刻意换浏览器、换网络来多投。对一个作品展来说可以接受。

1. **签名的匿名观测者 ID**：第一次投票时服务端生成一个随机 ID，带上服务端密钥的签名，写进 Cookie：`HttpOnly`、`Secure`、`SameSite=Lax`、路径限 `/api/votes/`，有效期两年。每卷两票的上限由服务端按这个 ID 在数据库里卡死，改前端或伪造 ID 都绕不过去。
2. **限制新 ID 的发放**：同一个 IP（加盐哈希后计）在一段时间里只能领有限个新 ID，反复清 Cookie 刷不出多少票。
3. **限频**：按 IP 和按观测者 ID，各限制每分钟的投票和撤回次数。
4. **实例上限**：票箱函数同时运行的实例数有上限。被高频刷的时候，超出的请求排队或被拒，不会把费用刷上去。

另留一个关着的开关：发现有人刷票时，可以在服务端打开无感校验。浏览器投票前要在后台先算一道小题，观测者看不到任何界面。

上面的具体数值（每小时几个新 ID、每分钟几次）写在部署配置里，不写死在代码里。

## 九、数据

### 9.1 存在哪

票数存在阿里云表格存储（Tablestore），实例和函数计算放在同一个地域。网站本身仍是 GitHub Pages 上的静态页，仓库里不放投票数据。

| 表 | 主键 | 内容 |
|---|---|---|
| `ballots` 观测票 | 观测者 ID、卷 key | 这位观测者在这一卷投了哪一两件作品（型号 id，最多两个）、投票时间、行版本号。写入时检查版本号，并发投票也不会超过两票 |
| `tallies` 计票 | 卷 key、型号 id | 票数，原子加减 |
| `voters` 观测者 | 观测者 ID | 发放时间、发放时 IP 的哈希 |
| `limits` 限频 | 维度（IP 哈希或观测者 ID）、时间窗 | 计数；表上设 TTL，过期自动删除 |

**投一票的顺序**：先条件更新 `ballots` 那一行，成功后再给 `tallies` 加一。万一加一失败，`ballots` 是准的，由每天一次的对账任务从 `ballots` 重算 `tallies`，修正误差。

**不存个人信息**：观测者 ID 是随机数，IP 只存加盐哈希，限频记录自动过期。

### 9.2 能投的名单

导出插件 `export.py` 多写一份 `votable.json`，随网站一起发布：`{"updated": …, "tasks": {"<卷key>": ["<型号id>", …]}}`。

- **谁进名单**：正式发布时，只列确认快照里已公开、`state` 为 `done`、并且挂出了图的作品。本地预览的 `data-local/` 里照同样的规则列。
- **函数怎么用**：按网址读取这份名单，缓存几分钟。新交卷的作品发布上线后自动可投，撤下的作品自动不可投。
- **不在名单里的作品**：它的旧票留在库里，但不计入任何显示。

### 9.3 发布时的快照

`publish.py` 正式发布时，从票数接口（`publish.json` 的 `votes_api` 下的 `/api/votes/v1/<专题>/tally`）取一份当时的计票，写进数据目录的 `votes.json`，格式和接口返回的一样。它有两个用处：
- 票箱连不上时，作为退路显示；
- 留档。哪天停掉后端，网站上仍有一份最后的票数。

## 十、服务端

### 10.1 部署形态

- **代码**：阿里云函数计算（FC 3.0）的一个 HTTP 函数，Node.js 写，代码在 `website/services/votes/`。
- **地址**：接口有自己的子域，是函数计算的自定义域名（HTTPS）：`https://api.wendystars.com/api/votes/v1/<专题>/…`。网站的 DCDN 路由不到这条路径，所以票箱不跟网站同一个域名。
- **跨域**：网站在 `https://octathlon.wendystars.com`，向接口发的是跨源请求。函数按 CORS 只放行这个源，并允许带凭据（`Access-Control-Allow-Origin` 写明这个源、`Access-Control-Allow-Credentials: true`）；投票和撤回是带 `Content-Type: application/json` 的 POST、DELETE，浏览器会先发一次预检（OPTIONS），函数照样回答。前端每个请求都带 `credentials: 'include'`。
- **Cookie**：两个子域同属 `wendystars.com`，是同一站点（same-site），观测者 ID 的 Cookie（`SameSite=Lax`、路径 `/api/votes/`，第八节）由 `api.wendystars.com` 发、随跨源请求带回去，不算第三方 Cookie。
- **前端怎么知道地址**：接口的源写在 `website/tools/publish.json` 的 `votes_api`；`publish.py` 构建时经环境变量 `ONESHOT_VOTES_API` 交给网站，页面里写成 `<源>/api/votes/v1/<专题>/`，部件里不写死。开发服务器用同源的本地票箱（第十一节）；没给这个变量的构建（本地看成品）用同源地址，看到的是「票箱暂时关着」。
- **缓存**：只有票数接口带 `Cache-Control: public, max-age=30`，其余接口一律 `no-store`。
- **扩展**：接口带专题和版本：`/api/votes/v1/<专题>/…`，以后别的专题要投票可以直接复用。

### 10.2 接口

路径都在 `https://api.wendystars.com` 下（开发时在开发服务器同源）。

| 方法与路径 | 做什么 | 返回 |
|---|---|---|
| `GET /api/votes/v1/aesthetics/tally` | 全部计票 | `{updated, voters, taskVoters: {卷key: 观测者数}, tasks: {卷key: {型号id: 票数}}}`，只含名单里的作品；`Cache-Control: public, max-age=30` |
| `GET /api/votes/v1/aesthetics/me` | 这位观测者投了什么 | `{votes: {卷key: [型号id, …]}}`；没有 Cookie 时是空的；`no-store` |
| `POST /api/votes/v1/aesthetics/vote` | 投一票，正文 `{task, model}` | 这一卷你的票和这一卷最新的计票；第一次投票时顺带发 Cookie |
| `DELETE /api/votes/v1/aesthetics/vote` | 撤回一票，正文 `{task, model}` | 同上 |

错误一律返回 `{error: <代码>, message: {zh, en}}`：

| 状态码 | 错误代码 | 含义 |
|---|---|---|
| 400 | `bad_request` | 正文格式不对 |
| 404 | `not_votable` | 这件作品不在名单里 |
| 409 | `limit_reached` | 这一卷两票已用完 |
| 409 | `already_voted` | 这件作品已经投过 |
| 429 | `rate_limited` | 限频，带 `Retry-After` |
| 503 | `closed` | 票箱关闭，比如维护 |

### 10.3 存储接口

函数里的存储层是一个接口，有两种实现：
- 表格存储：线上用；
- 内存：本地开发和测试用。

规则（每卷两票、不能重复、名单校验、限频）写在存储层之上，两种实现共用同一份规则代码。

## 十一、本地开发与测试

- **本地票箱**：`npm run dev` 的开发服务器在 `/api/votes/` 挂一个本地票箱，用的是同一份函数代码配内存存储，前端在本地就能完整地投票、撤回、看排名。重启开发服务器后票清零。

## 十三、阿里云上要由账号主人做的事

1. **开通服务**：开通函数计算和表格存储，选按量付费。
2. **建部署用的子账号**：在 RAM 访问控制里建一个只用于部署的子用户，只给 `AliyunFCFullAccess` 和 `AliyunOTSFullAccess`，生成 AccessKey，在本机终端里自己录进部署工具。
3. **配接口的子域**：函数部署好之后，把 `api.wendystars.com` 绑成函数的自定义域名（HTTPS），在域名解析里把它指过去（第十节）。
4. **可选**：在费用中心设一个月度预算告警。
