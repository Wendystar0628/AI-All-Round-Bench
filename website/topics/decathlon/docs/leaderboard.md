# 排行总榜 `/leaderboard/`

控制台子页面：命令栏 → 页名 → 工具条 → 一张一模型一行的排行图，可换五种视图和对比视图 → 排行图下面一块成绩与开销（散点图和帕累托前沿）→ 一块成绩矩阵（模型 × 13 题）。本文后半的“共用部件”（模型行、工具条、筛选、对比、模型侧面板）题目类别榜也用。

## 内容

- 每个模型一行：名次、厂商图标、全名、总分。现在 7 行：GPT 6 Astra 74.7、GPT 6.1 Sol 74.3、Claude Opus 5.5 73.8、Claude Sonnet 5.5 67.7、GPT 6.1 Terra 59.9、Claude Haiku 5.5 49.1、GPT 6 Luna 34.0。
- 页名 `// LEADERBOARD` / 排行总榜，字段 `2026.11.04 更新 │ GitHub 仓库`（日期取 scores.json 的 `updated`，仓库链接与首页共用 `ui/repo.js`）；右侧三个大数字讲比赛规模：参赛模型（小字“另有 N 个评测中”）、题目（小字“N 个类别”）、每题时限（分钟，小字“无人答疑，到时中止”）。
- 两类题分取 scores.json 的 `kinds`：标准评判题分 = 数学推理、性能优化、算法对抗、空间推理、识图建模按权重平均（合计 50），主动设计题分 = 其余 5 类按权重平均（合计 50）。例：Astra 72.6 / 76.1，Opus 52.6 / 87.9，Haiku 26.8 / 63.9。
- 页脚一句“总分 = 10 个类别按权重相加，类别分是该类各题的平均”，链到 `/about/`。
- **测试开销与 Token**（约定见 `orchestrator/docs/测试开销.md`，数据是 scores.json 的 `scores.<id>.cost` 和顶层 `cost_source`）：每个模型仍是一行，分数右边多两列，同一行、竖直居中、右对齐。「测试开销」列写金额 `¥45.1`，后跟一个很小的依据记号（形状区分、不只靠颜色）：○ 圆环＝按订阅折算（`basis` 为 subscription），◆ 实心菱形＝按 API 标价折算（api）；金额为 null 时写“数据暂缺”。「Token」列写已答各题合计（全套测完即 13 题；评测中模型只算已出的题，测试开销同理），中文按“亿”写（`17.1 亿`，不足 1 亿写“万”），英文用 B/M（`1.71B`），`tokens` 为 null 时写“数据暂缺”；`fitted` 非空（有题没有用量记录、按估算）时后跟一个 `*`。
- 记号只解释一次：看板头右侧（「存为图片」左边）一行图例“○ 按订阅折算　◆ 按 API 标价折算　* 含估算（部分题没有用量记录）”，英文“○ Sub-prorated　◆ 按 API 标价折算　* includes estimates (tasks without usage records)”；数据里没有的记号不列。“按订阅折算”“按 API 标价折算”不在每行重复。
- 页脚第二段写测试开销的说明，三行：
  1. 换算依据：订阅模型按每周额度（数据来自 `cost_source.name`）把用掉的额度折算成订阅费，没有额度数据的按官方 API 价格估算；API 模型按本地逐次请求用量及官方标价计算，按请求时间选择适用时段；1 美元 = `usd_cny` 元，额度数据 `fetched` 日期。
  2. 订阅额度数据来源：完整写出 `cost_source.url`（现为 `https://modeldial.com/subscriptions?period=week&view=insights`，从数据读，不写死），可点，新窗口打开。
  3. 复测说明（用户指定）：“如对模型实测消耗量有疑惑，可自行从 GitHub 下载试题及其隔离环境，自行测试后对比。”后接仓库地址 `github.com/Wendystar0628/AI-All-Round-Bench`（可点，新窗口）。英文版：“If you doubt the measured usage, download the tasks and their isolated environments from GitHub and run them yourself to compare.”
  长网址在手机宽度下任意处折行，不撑出横向滚动。
- 数据里一条 cost 都没有（老数据）时不出这一列和这句页脚，版面照旧。

## 版式

- 从上到下：页名区（左边眉标、标题、字段，右边三个大数字）→ 工具条 → 轴条 → 模型行。
- 内容最宽 88rem，居中。图区占去勾选、名次、名字、分数和测试开销列以外的全部宽度。
- 测试开销、Token 两列在分数列右边（6.25rem、5.5rem），行高不变、上下留白均匀；表头写“测试开销”“Token”。对比视图没有这两列，“差”占分数和这两列。
- 手机宽度（≤ 599px）不出现横向滚动：页名的三个大数字排到标题下面，工具条的按钮随窗口折行；看板内边距收窄。工具条不出「对比」（对比在桌面上做，同题目类别榜），每行排成两行：名字和分数 → 图区和分数下面的测试开销（金额加记号，一行）；Token 消耗和 TPS 两列收起，在浮签和侧面板里看。名次和图标竖跨两行。轴条随之变成上面列名、下面刻度，图区窄时刻度只标 0、60、100，矩阵格放不下数字时只留色阶。
- 排行图放在一块看板里，看板顶边紫页签；轴条和工具条一起吸顶在命令栏下。

## 视图

五个视图用工具条上的「图表」选项按钮切换（切换每行画的是哪种图），**行序只由“排序”决定，切视图只换每行的图区和轴条，同一模型始终在同一行**；对比视图不在「图表」里，从工具条的「对比」进入（共用部件「对比」）。0–100 的视图共用同一把固定刻度（不随数据缩放，新模型加入不改已有柱长），20 / 40 / 80 画淡网格，60 画一条青色虚线（青 800）标“及格线”。本视图所画那个量的最高者：数字用荧光绿高光，旁边一颗荧光绿四角星。颜色按 [visual.md](visual.md)。

1. **总分**（默认）——谁总分最高。横向柱从 0 长到总分。柱紫 300；指向和勾选的紫 600。第一名柱尾挂荧光绿四角星，分数荧光绿高光。
2. **及格线**——离 60 分差多少。同一刻度，柱从 60 起画：高于 60 向右、紫 300；低于 60 向左、浅灰填充加 1px 次要墨边。60 那条基准线是青 800 实线，两侧各一窄条青 100 底标出及格线附近。柱端写差值：Astra +14.7、Terra −0.1、Luna −26.0；差值很小的柱也留一个看得见的最小长度。刻度改标 −60…+40，轴条右端写“及格 4 │ 未及格 3”。差值最大的挂荧光绿四角星。
3. **得分构成**——总分由哪些类别贡献。每类贡献 = 类别分 × 权重，10 段按类别表顺序从 0 往右叠，末端就是总分。每段用 visual.md 的类别固定颜色：前 5 段（标准评判题）荧光绿族加 1px 墨边，后 5 段（主动设计题）紫族；段间 1px 板色缝，荧光绿段和紫段之间是一道墨线。轴条换成图例：组名“标准评判题 50 │ 主动设计题 50”，下面 10 个类别名带权重，色块和图形一致。指向图例或任一段：其余段退淡，所有行该类的段保持原色并在段内写贡献值，该类贡献最高的那段挂荧光绿四角星；平时段内不写数字。
4. **两类题**——偏标准评判题还是主动设计题。哑铃：同一刻度上标准评判题分画荧光绿方块加墨边，主动设计题分画紫色四角星，中间 1px 次要墨连线。Opus 52.6 → 87.9 一条长线，Astra 72.6 → 76.1 几乎重合。两类各自的最高分，数字用荧光绿高光（标准 Sol 73.1，设计 Opus 87.9）。勾选的行连线加粗、变紫 600。轴条右端是图例。
5. **类别矩阵**——每个模型在 10 类上的强弱。图区换成 10 个等宽格，格里写分数，底色按分数分 5 档（顺序配色，0–20 最浅）：标准评判题五列用荧光绿 100 到 500，主动设计题五列用紫 100 到 300，墨字都可读。每列最高的格加粗、右上挂一颗荧光绿四角星（Opus 系统架构与实现 91.1）。表头是类别图标、名称、权重，名称链到题目类别榜。看板头的「粒度」选项按钮（类别 / 题目）：切到题目时 10 列按类别分组，列头写题号 01–13，指向显示题名；没出分的格铺斜线纹。
6. **对比**——勾选的 2–4 个模型逐项差多少。在对比栏按「查看对比」进入，按「返回榜单」或关掉对比回到原来的视图；唯一不按模型分行的视图：行换成总分、标准评判题、主动设计题和 10 类（“题目”粒度时再加 13 题，和矩阵共用「粒度」），每行 2–4 根细柱按勾选顺序排，颜色依次是紫 500、荧光绿 500、星光青 500、墨（后三种加墨边），柱前写勾选序号和简称（`01 6.1Sol`）；每行最高的数字用荧光绿高光，右端写最高减最低（总分“差 0.9”）。

**模型多到几十个时**：五个视图仍一模型一行，行高固定，超过 20 个在榜单窗口里滚动，工具条、轴条、矩阵表头吸顶；总榜不分页。要少看几个用筛选。对比最多 4 个。

**看板头的开关**：「开销：订阅折算 / API 标价」切换测试开销的口径（订阅折算：有订阅的按套餐折算、没有的按 API 标价；API 标价：一律按官方标价逐次计算），金额、按开销排序和侧面板一起变，写进地址 `?cost=api`。看哪些模型由工具条的筛选决定。

**排序 = 依据 + 方向**：依据在「排序」选项按钮的菜单里选——总分、标准评判题、主动设计题、10 个类别，数据里有开销时再加测试开销、Token 消耗、TPS 三个资源列；方向由它旁边的「↓ 降序 / ↑ 升序」按钮切换。四个列头（总分或当前在排的分项、测试开销、Token 消耗、TPS）也是排序按钮：点没在排的列按它排，点正在排的列翻转方向；在排的列头加紫色下划线和 ↓ / ↑，其余列头带淡色 ↕。新换的依据从默认方向开始：分数、Token、TPS 从高到低，测试开销从低到高。

所有依据共用一套排名：有值的按方向排，值相同（按显示精度）同名次（1、1、3），再按总分（含自定义权重）和名字；没有值的排在后面——已排名的名次写「—」，评测中的照旧写评测中。名次列显示当前顺序下的名次，表头写依据和方向（`名次│性能优化 ↓`）；按总分从高到低时不写依据，自定义权重的升降箭头只在这时出现。按资源列排时图区画该资源（自己的刻度，没有及格线）。地址 `?sort=` / `?dir=`（默认方向不写），刷新和分享不丢；数据下载按当前排序输出。拖权重沙盘会回到按总分从高到低。点图例或矩阵表头的类别名不排序，只跳转。视频里的总榜仍按总分排名。

## 成绩与开销

排行图下面一块看板（`src/pages/leaderboard/frontier.js`）：`// Score × cost` / 成绩与开销，副题“花多少钱换多少分”，回答谁用更少的开销拿到更高的分。

- 一个模型一个点，两条轴都是线性坐标。横轴是测试开销，按看板头「开销」的口径（订阅折算 / API 标价，和排行图的「开销」同一个开关，两处任选一处切换）；纵轴由看板头「纵轴」选项按钮决定：总分、标准评判题、主动设计题和 10 个类别，分组同工具条的「排序」，写进地址 `?fy=`（总分不写）。
- 纵轴选题型或类别时，横轴开销按题目时长折算：整套开销 × 这些题的限时合计 ÷ 13 题限时合计（数学推理 13.2%）。图下写一句折算说明，浮签里写“整套 ¥x × 时长占比”。
- 只画全套测完、有开销数据的模型（评测中的、没有开销的不画，图下写各几个）；跟随筛选和自定义权重（总分）。
- 点：厂商图标放在小圆盘上，旁边写模型名；名字自动避开别的名字、图标和连线，紧挨着自己的点，不画引线。手机宽度下图更高、图标更小，只写前沿上的名字，其余靠点按看。
- 帕累托前沿：没有别的模型开销更低（或相同）且得分更高（或相同）的模型，按开销从低到高用紫色折线连起来，前沿的点圆盘描紫边、名字紫色加粗，折线下方淡紫铺底。各厂商自家的前沿（只在本厂商的模型里算）用灰色细线连，自家前沿只有一个点的不连。
- 指向或聚焦一个点：它和同厂商的点、同厂商的线留着，其余退淡；从点向两条轴画虚线引导，轴上用墨底小块标出开销和得分；浮签写全名、得分和名次、开销和依据（题型或类别时加折算）、Token（总分时），以及它在前沿上，或被哪个前沿模型以更低开销、更高得分超过。点击（键盘 Enter）打开模型侧面板。
- 图下一行列出前沿上的模型（图标、名字、得分、开销），指向时图里对应的点亮起，点击打开侧面板。看板头右端「存为图片」：当前纵轴、口径和筛选下的图，前沿模型列在页脚对照。
- 入场：第一次滚到时点从横轴升起，再画前沿折线，名字和厂商线随后淡入；换纵轴、换口径、改筛选或权重时点和线平移到新位置。

## 成绩矩阵

排行图下面单独一块看板：`// Score matrix` / 成绩矩阵，副题“每道题谁高谁低”，回答每道题上各模型的高低。总榜和题目类别榜的“矩阵”视图用的是同一个部件，区别只在列和最后一列。

- 结构：一模型一行，列是 13 题，按类别分组；分组表头是类别图标、简称、权重（链到题目类别榜），下面一行列头写题号和题目简称（取 tasks.json 的 `short` / `short_en`），最后一列是总分。题目类别榜里只有本类的题，不分组，最后一列是类别分。
- 行头：名次、勾选框（只在对比模式）、厂商图标、全名（链到模型得分页）；点行的其余部分（格也算）打开模型侧面板。名次是当前排序下的名次，没有分的写“—”。
- 格：写分数，底色按分数分 5 档，和“类别矩阵”视图同一套顺序配色（标准评判题荧光绿族、主动设计题紫族）；每列最高的格加粗、挂荧光绿四角星，并列都标。评分员写了分数异常说明的格，角上一道短斜线。没分的格灰底铺斜线纹，写短标记：评测中、未交、失败（评分员没给总分写“—”），判定取 scores.json 的 `task_info`（见 tools/README.md）。
- 排序：默认按最后一列（总分或类别分）；点题目列头按这道题从高到低排，列头和这一列标出来，再点一次恢复默认。只管本矩阵，不跟排行图的排序和权重沙盘，也不写进地址。看板头右端写提示“点题号按这道题排序，再点恢复按总分”和「存为图片」（成绩矩阵的分享图：全部模型，附题号对照）。
- 指向一格出浮签：模型全名 │ 题号题名、分数 │ 题内名次 / 已排名数；权重；设计题有两位评分员时写各自的分（平均就是题分）；有分数异常说明时逐条写评分员和说明。没分的格写原因（评测中，还没出分 / 未交答案 / 评分失败，还没出分 / 评分员没给总分），总分和类别分写已出几题。
- 筛选、勾选和排行图联动；对比模式下勾选的行左边紫条。手机宽度下表格横向滚动，模型列留在左边。

## 权重沙盘

- 工具条右端次要按钮「调整权重」（`W`），在轴条上方展开一条面板，不遮挡榜单；再按一次收起，已改的权重保留。
- 面板里 10 个类别各一个滑块，0–30%，步长 0.5%，旁边写数值；实际权重 = 滑块值 ÷ 10 个之和，面板右端写当前合计并显示归一后的各类百分比。
- 预设筛选块：官方权重、各类均等（官方权重本身各类相等时不出现）、只看标准评判题、只看主动设计题；加一个「恢复官方权重」。
- 生效时：
  - 总分、及格线、得分构成三个视图按自定义权重重算，名次跟着变；两类题、类别矩阵、对比不受影响。
  - 分数列表头写「自定义总分」，名次旁小字写和官方名次的差（`▲2`、`▼1`）。
  - 页名下出现提示：荧光绿小旗加「正在使用自定义权重，名次不是官方结果」和「恢复官方权重」。
  - 权重写进地址 `?w=10,10,10,10,10,10,10,10,10,10`，可分享。
- 拖动滑块时柱形变形跟着走，松手后行重排。评测中的模型照旧不参与。

## 共用部件

### 模型行

- 列：（勾选框）│ 名次 │ 厂商图标 │ 全名 │ 图区 │ 分数（│ 测试开销 │ Token，`cost: true`，只有总榜开）。行高固定，行间 1px 细线，不用斑马纹。
- 勾选框：平时没有这一列，只在对比模式出现（总榜、题目类别榜的每种视图都一样）；可点区 32px，方形，勾选色紫。
- 名次：两位宽体等宽数字 `01`；同分同名次，下一名跳号（1、1、3），同分按全名排。
- 厂商图标：有彩色版 `platform/厂商图标/mark/<logo>-color.svg` 的用彩色版，深色主题也不反色；没有的用单色版 `<logo>.svg`，跟随文字颜色。任何状态都不染紫或荧光绿。
- 全名：界面字体，标签字重，后接推理强度 `(xhigh)`（Saira，小一级，次要墨，见总览「数据」）；名字列放得下大多数全名，放不下时省略名字、保留括号，指向时显示全名；全名是链接，到模型得分页 `/models/<id>/`（名字接力）；点行的其余部分打开模型侧面板。
- 分数：宽体粗字，字号比名字大，等宽数字、一位小数、右对齐；第一名垫荧光绿（`.st-hi`）。
- 指向或聚焦一行：左边落紫条、底色变纸色、图形加深一档（紫 300 → 紫 600，荧光绿 500 → 荧光绿 600）；不右移，柱子保持对齐。对比模式下，勾选的行左边常显紫条、图形加深一档。
- 测试开销格、Token 格：各一行，右对齐。金额宽体粗字（比分数小一级，等宽数字、一位小数），后跟依据记号（○ / ◆，次要墨，0.5rem）；Token 宽体等宽数字，后跟 `*`（次要墨，不含估算时留出同宽的空位，让数字对齐）。不染主题色，不做最佳高光。指向这两格出浮签（交互一节），金额在打开页面时随分数列落定。
- 读屏把一行读作“第 1 名，GPT 6 Astra，74.7 分”，有测试开销时接“，测试开销 45.1 元，按订阅折算，1.3 亿 Token，含估算”；图形 `aria-hidden`；矩阵和对比用真 `<table>`。

### 工具条

- 吸顶。左端两个模式按钮「筛选」「对比」：漏斗、长短三横的小图形加字，墨色细边，一眼认得出；打开的那个是当前项样式（淡紫底、左边紫条）。两个模式一次只开一个，`F` / `C` 开关，在工具条里按 `Esc` 关。右端是本页的工具，「下载数据」在最后。
- 打开的模式在工具条下面展开一块面板，随工具条吸顶，高了在面板内滚动；平时榜单行没有任何勾选框。
- 工具条只占一行：两个模式按钮后面接本页的控件（总榜是「图表」「排序」两个选项按钮和升降序），右端是本页的工具（总榜的调整权重、下载数据）；窗口窄了才折行。题目类别榜下面挂类别跳转条。

### 控件

- 凡是调整榜单怎么显示的东西（工具条的筛选、对比、图表、排序、升降序、调整权重、下载数据，看板头的开销、粒度，题目类别榜每块看板的图表）都是同一种按钮：2.25rem 高、1px 墨色边框、面板底色、切角，指向时荧光绿擦入；打开的模式或菜单是当前项样式（淡紫底加紫条）。
- 有几项可选的（图表、排序、开销、粒度）是选项按钮（`ui/choice.js`）：按钮上粗体写组名，一道细竖线后写当前值，末尾小箭头，例如「图表 │ 总分 ▾」「排序 │ 总分 ▾」。点开在按钮下方展开选项菜单，当前项淡紫底加紫条；图表的每项下面一行小字写它回答什么问题（“谁总分最高”“离 60 分差多少”…），右边是快捷键 1–5；排序的选项按「分数 / 类别 / 开销与速度」分组。选一项就收起；Esc、点别处、滚动页面也收起；↑ ↓ 在选项间移动。

### 筛选

- 选这一页看哪些模型，只隐藏行、不改名次；总榜（排行图、成绩矩阵）和题目类别榜（三种视图）都按它显示，存为图片和 CSV 也只含看的模型。
- 面板：标题「筛选模型」和「显示 12 / 23 个模型」；快捷组「全部 / 御三家 / 外模 / 国模」（御三家是 OpenAI、Anthropic、Google，外模 / 国模按 models.json 的 `region`），当前选法正好是某一组时那块是当前项；一个在列表里找模型的输入框（只筛面板里的名单）；「全不选」「完成」。
- 下面按厂商分组：组头一个勾选框管整组（只选了一部分时是半选），后面厂商图标、名字、模型数；组内每个模型一个勾选框，简称加推理强度，按总分名次排。没选的模型名字变淡。点一下就生效。
- 关上面板后，有筛选时按钮后写 `12/23`，旁边一行「只看 12 / 23 个模型　清除筛选」。
- 筛选写进地址 `?show=<id>,<id>`（全部时不写），在总榜和题目类别榜之间沿用（sessionStorage）。

### 对比

- 按「对比」进入对比模式：每个模型行（总榜各视图、成绩矩阵、题目类别榜的三种视图）左边出一列勾选框，下面的对比栏写「对比（最多 4 个）」、已勾选的模型（序号加简称的小块，左边一道该模型的对比色，点一下取消）、「清空」、主要按钮「查看对比」（不足 2 个时不可按）和「完成」。勾选的行常显紫条。
- 勾选最多 4 个，序号 01–04 按勾选先后；满 4 个时其余勾选框不可按，指向提示“最多对比 4 个”。关掉对比模式勾选框收起，已勾选的保留，「对比」按钮后写个数。
- 「查看对比」：总榜切到对比视图（按钮变「返回榜单」）；题目类别榜跳到 `/leaderboard/?view=compare&cmp=…`，到了直接是对比模式。
- 视图、排序、勾选写进地址：`?view=total|pass|parts|kinds|matrix|compare&sort=<类别或 total/standard/design>&cmp=<id>,<id>`，刷新和分享不丢。勾选在总榜、题目类别榜、模型得分页和侧面板之间沿用（sessionStorage）。

### 模型侧面板

- 点行（全名以外的部分，矩阵里的格也算）打开，地址加 `?model=<id>`。从右侧推入，宽度放得下一行“类别名、权重、细柱、分数、名次”，内容超高时面板内滚动。
- 以 Astra 为例，从上到下：
  - 标题：眉标 `// No.01 / OpenAI`，图标加全名；字段 `Codex │ xhigh │ 2026.11.04 测评`。
  - 三个大数字：总分 74.7（第 1 名，垫荧光绿）、标准评判题 72.6、主动设计题 76.1。
  - `// TEST COST` / 测试开销（数据里有开销时）：一行写金额加依据（`¥45.1 按订阅折算`），下面字段写套餐（`套餐 OpenAI Pro 200（$200/月）`，API 模型写“按 DeepSeek API 官方标价”）和 Token（`13 题合计 1.3 亿 Token（含估算）`；题数取 `cost.tasks`，评测中模型只算已出的题），再下面小字说明金额怎么来的（按 ModelDial 每周额度折算 / ModelDial 无额度数据，按官方 API 价格估算（API 等值 $122.2）/ 按会话消耗的积分折算），有拟合时列出拟合的题（13 题都拟合时写“13 题都没有用量记录，全部按估算”）。
  - `// CATEGORIES` / 10 类：每行类别名（链到题目类别榜）、权重、细柱、分数、类内名次（数学推理 10% 78.0 1 / 7）。类内第 1 的分数垫荧光绿。
  - `// TASKS` / 13 题：按类别分组，题名（链到题目页）、分数、题内名次（数学竞赛原创试题 81.0 3 / 7）。没出分的题写“未出分”，铺斜线纹。
  - 底部：主要按钮“查看全部得分”→ `/models/<id>/`（模型得分页），次要按钮“加入对比”（已勾选时为“移出对比”）、“上一个”“下一个”按当前排序换模型。
- Esc、“关闭”、点遮罩关闭。

## 交互

- 视图用数字键 1–5 切；选项菜单里 ↑ ↓ 移动。
- 全站只有一种悬停说明框：墨底直角的浮签（ui/tip.js）。不用浏览器自带的 title 小框；元素上写的 title 由外壳统一接管，悬停或聚焦时以浮签显示。列头、开关、排序按钮不加说明文字。
- 指向图形出现小提示（墨底直角小块，字段字号），键盘聚焦行时同样出现：构成写“数学推理 78.0 × 15% = 11.7”，两类题写两个分，矩阵写“Claude Opus 5.5 │ 系统架构与实现 91.1 │ 1 / 7”。
- 指向测试开销格：浮签逐行写“模型 │ 测试开销 ¥45.1 按订阅折算”、套餐、Token 合计（含估算时注明），以及金额的来历（`method`：quota 按 ModelDial 每周额度折算；api_price 按 basis 区分：订阅写“ModelDial 无额度数据，按官方 API 价格估算”并附 API 等值美元；API 写“按本地逐次请求用量套官方 API 标价”；credits 按积分折算）和拟合的题。键盘和触屏用户在侧面板里看到同样的内容。
- 打开页面时数据来自地址里的视图、排序和勾选；没有就用总分视图、按总分排。

## 空状态与评测中的模型

- 评测中（13 题没出齐）：排在已排名模型之后，名次列写虚线框“评测中”，分数写“—”；图区铺斜线纹并写“已出 8 / 13 题”；矩阵里出齐的类照常上色，其余格斜线纹；侧面板照常列已出的分。不参与最高者高光和及格计数，也不计入页名的“参赛模型”（另记在“另有 N 个评测中”）。
- 筛选后没有模型：“筛选里没有选中的模型。打开筛选勾选模型，或清除筛选。”
- 对比不足 2 个：“勾选 2 到 4 个模型，这里会逐项并排比较它们的分数。”
- 加载中：几行骨架，数据到了硬切成内容、逐行亮起。读取失败：提示“成绩数据没有读到，刷新页面再试一次。”

## 动效（参数见 motion.md）

## 通向哪里

- 全名 → 模型得分页 `/models/<id>/`；行的其余部分、矩阵格 → 模型侧面板。
- 类别名（构成图例、矩阵表头、侧面板）→ `/categories/#<类别>`。
- 题名（侧面板、矩阵题目列头的提示）→ `/tasks/<类别>/<题目>/`。
- 成绩矩阵：全名 → 模型得分页，行的其余部分和格 → 模型侧面板，分组表头的类别名 → `/categories/#<类别>`。
- 页脚 → `/about/`；对比栏「查看对比」在本页切到对比视图。
