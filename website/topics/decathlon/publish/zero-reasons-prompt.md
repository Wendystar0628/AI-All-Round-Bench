任务：为成绩网站「0分盘点」页调查下列模型在指定题目上得 0 分的原因，写成给普通读者看的简短解释（中英各一句），加进 `website/topics/decathlon/publish/zero-reasons.json`。

材料位置（全部只读）：
- 评分记录：`orchestrator\grading\decathlon\<厂商>\<型号>\<题名>\<评分员>\<阶段>\`。prompt.txt 写明了作答目录和评分要求，result.json 是评分结果，session.log 和 work\ 是评分过程。评分表在 prompt.txt 指向的位置（评分表_6.1Sol.md 等）。
- 作答目录：以 prompt.txt 里写的路径为准。已归档的看 `archives/decathlon/<厂商>/<型号>/`。
- `python orchestrator\grading.py status decathlon` 可看各模型各题的分数、关键数值、备注和「分数异常」说明。
- 需要时可以读受测模型的会话记录，确认它做了什么。

规矩：
- 只读调查。除了 zero-reasons.json，不创建、不修改、不删除任何文件；不动作答目录、评分记录、会话记录、题面和评分指南。
- 不重新评分、不重跑评测、不跑 GPU 或长时间程序。靠评分记录、日志和读源码判断；确有必要只做秒级的小检查。
- 解释里不透露评分指南细节、隐藏测试数据或参考答案，只说模型交了什么、哪里出了问题。
- 分数照现有记录，不质疑、不改分，只解释为什么是 0。

每条的写法：
- zh：一到两句中文，50–80 字左右，最多 90 字。讲清三件事：交了什么或做到哪一步；具体卡在哪、错在哪；为什么整题是 0。可以带关键数字（交了几题、几个测试全错、慢几倍、时间花在什么上）。每个细节都要有记录可查，不猜、不编。普通读者能看懂，术语少用、用到就顺手解释。不写型号名和题名（页面上已有），不写「该模型」「因此得零分」。
- en：同义的英文，一到两句，最多 50 个词，同样不写型号名、题名和 "scoring zero"。
- kind：从下面五个里选最主要的一个。
  - none：没交出东西（没写出答案或作品，或只交了空壳、草稿，如证明留着 sorry）
  - crash：交了但跑不起来（编译失败、运行崩溃、超时、启动卡死）
  - wrong：能跑但结果不对（输出错误、没有一项判对）
  - slow：结果对但没达到计分门槛（如比基线还慢，没有加速）
  - rule：违反题目规定（用了禁止的工具或做法）

写入：zero-reasons.json 按题名再按型号存，例如 `{"鲁班锁拆解": {"Hy/Hy4": {"kind": "rule", "zh": "……", "en": "……"}}}`。只新增或替换清单里的条目，不动其他条目，保持 UTF-8 和原有缩进风格。写完用 python 读一遍，确认是合法 JSON。最后回复一句完成说明。
