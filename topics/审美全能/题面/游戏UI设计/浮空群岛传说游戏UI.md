# 游戏UI设计：动作角色扮演游戏《浮空群岛传说》

## 1. 目标总览

为一款名为《浮空群岛传说》的游戏设计核心的游戏 UI 及其动效。UI 用网页实现，做成可以操作的界面演示。

**游戏类型：第三人称动作角色扮演游戏（ARPG），四人小队、任务制。**

这是一道纯 UI 与动效的设计题：画面里只有游戏界面本身，角色、首领和场景都只以名字、图标和数值的形式出现在界面里，界面下方配一个简洁的背景来衬托。

游戏讲的是一支飞空艇队伍在浮空群岛间远航、讨伐巨兽的冒险。你要设计的是这款游戏最核心的 7 个界面，第 4 节逐一列出每个界面要有的内容：标题、任务、编队与养成、战斗、奥义演出、结算和剧情。

每个界面都要：
- 有完整的版式和视觉设计；
- 有真实可用的交互：悬停、选中、确认、切换、返回都有反馈；
- 有动效：界面的进出、数值的变化、状态的切换都有过渡，重要的时刻有演出。

界面之间按游戏流程串成一条完整的体验：标题 → 剧情 → 任务 → 编队 → 战斗 → 结算。观看者可以自己操作，把每个界面都点一遍；作品也内置一段演示录像，能直接导出成视频。

这是一道主动性扩张的审美设计题：题面给出游戏设定和每个界面要做的内容，视觉风格、版式、图形和动效全部由你设计，也可以在此基础上加入你自己的构思。作答过程中反复对照本题面逐项检查和完善。

## 2. 游戏设定

### 2.1 世界观

- **浮空群岛**：天空中漂浮着成千上万座岛屿，岛下是无边的云海。
- **飞空艇**：岛与岛之间靠飞空艇往来。驾驶飞空艇在群岛间接受委托、讨伐魔物的人，被称为「空行者」。
- **天渊兽**：沉睡在群岛深处的远古巨兽。它们接连苏醒，岛屿的平衡开始崩坏。
- **主线**：一支空行者队伍驾驶飞空艇「晨星号」远航，一边讨伐苏醒的天渊兽，一边追寻一个传说：云海之下，还有一片没有人见过的大地。

### 2.2 游戏类型与玩法

- 第三人称的动作角色扮演游戏。四人小队：玩家操作一名角色，另外三人由队友 AI 操作。
- 任务制：在任务柜台接下任务，出击到各座岛屿讨伐首领，结算后带着奖励回来。
- 战斗的核心机制，在战斗界面里都要表现出来：
  - **技能**：每名角色装备 4 个技能，各有冷却时间。
  - **奥义**：每名角色有一条奥义槽，攒满后释放必杀技。
  - **连锁奥义**：几名角色接连释放奥义，连成连锁；四人全员连锁时打出最强的终结技，终结技按第一个释放者的属性变化。
  - **连携**：全队的连携值攒到 100% 后进入「连携时刻」，敌人的动作变慢，全队获得强化。
  - **超载与破防**：首领被打出足够的伤害后进入「超载」，变得更凶猛；在超载中继续压制，首领就会「破防」，短时间内无法行动。
- 养成：角色等级、武器、4 个技能的搭配，以及可以自由镶嵌的「徽印」：每枚徽印提供一种特性，同类特性可以叠加。
- 属性：火、水、土、风、光、暗六种。
- 稀有度：铜、银、金三档。

界面里出现的角色和首领，只用下面这些名字、武器类型和属性：

| 角色 | 武器 | 属性 |
|---|---|---|
| 艾琳 | 单手剑 | 风 |
| 罗克 | 长枪 | 火 |
| 希娅 | 法杖 | 水 |
| 巴尔多 | 大斧 | 土 |
| 凛 | 双刀 | 暗 |

- 演示中出击的四人小队是艾琳、罗克、希娅、巴尔多，玩家操作艾琳。
- 演示用的任务：「熔炉之巅的咆哮」，首领讨伐任务，难度「极难」，地点是火山岛的熔岩竞技场。
- 首领：天渊兽「焰冠龙 伊格瑞斯」，火属性，弱点是水属性。
- 其余的数值、技能名、奥义名、道具名和对话文字由你编写。

## 3. 美术方向

- 游戏的气质是日系奇幻冒险：明快、热血、浪漫。整套 UI 的视觉风格由你确定，7 个界面统一在同一套视觉语言里。
- 六种属性、三档稀有度各有一眼认得出的视觉标识。
- 属性、武器类型、任务类型、技能和道具都有成套的图标。
- 界面文字用中文，可以搭配英文。

## 4. 界面清单

所有界面都按 16:9 的画面设计。每个界面下面写了它要有的内容，以及要有的交互和动效。

### 4.1 标题画面

- **内容**：
  - 游戏标志《浮空群岛传说》，带英文副标题「Legend of the Floating Isles」；
  - 「按任意键开始」的提示，按下后展开主选单：继续游戏、新游戏、设置。
- **交互与动效**：标志的入场；选单项的悬停与选中；确认后转场。

### 4.2 任务柜台

- **内容**：
  - 任务列表，按难度分档：普通、困难、极难、传说；
  - 每条任务显示名称、任务类型、地点、推荐战力和主要奖励；
  - 选中任务的详情：目标说明、可能获得的奖励、首领的名字和属性；
  - 推荐战力和当前队伍战力的对比；
  - 「出发」按钮。
- **交互与动效**：切换难度档；选中任务后显示详情。

### 4.3 编队与角色养成

- **编队**：
  - 四个编队位，每个显示角色的名字、武器类型、属性、等级和战力；
  - 一号位是「操作角色」；
  - 队伍总战力和任务推荐战力的对比，以及「出击」按钮。
- **角色养成**：点开一名角色，打开这名角色的详情：
  - 等级与经验，攻击、生命、暴击等属性数值；
  - 武器：名字、等级和属性；
  - 技能：4 个技能槽，每个技能显示名字、冷却时间和效果说明，可以从技能列表里选择替换；
  - 徽印：一排徽印槽，每枚显示特性名和等级；全身特性的汇总，同类特性叠加后显示总等级。
- **交互与动效**：
  - 点击编队位，从角色列表里换人；
  - 更换技能或徽印时，属性数值实时预览，看得出哪些提升、哪些下降；
  - 按下「出击」后转场进入战斗。

### 4.4 战斗画面

战斗画面是整套 UI 的重点，要把 2.2 节的战斗机制都清楚地呈现出来，信息多而不乱，战斗区域留给战斗本身。

- **队伍信息**：
  - 四名队员的名字、等级、属性、生命和奥义槽；
  - 操作角色的信息更醒目；
  - 奥义槽攒满时有提示。
- **首领信息**：
  - 首领的名字、等级、弱点属性；
  - 多层的生命，以及剩余层数；
  - 模式槽：攒满后进入「超载」，超载中打空进入「破防」。
- **锁定**：锁定目标的标识。
- **连携值**：全队的连携百分比；到 100% 进入连携时刻，连携时刻里连携值逐渐消耗。
- **技能栏**：4 个技能，各自对应的按键、冷却状态与剩余时间；冷却结束、可以使用时有提示。
- **伤害数字**：普通伤害、暴击、弱点属性伤害三种看得出区别。
- **战斗中的演出**：
  - 首领登场：首领的名字和称号；
  - 进入连携时刻，全队的强化状态；
  - 首领进入超载的警示；
  - 首领破防。

### 4.5 奥义与连锁奥义

- **奥义**：释放时的奥义演出，显示释放者、属性和奥义名，随后是奥义的伤害数字。
- **连锁奥义**：
  - 其他队员在短时间内接着释放奥义时，连成连锁，连锁数从 2 增加到 4；
  - 四人全员连锁时，出现「全员连锁」，打出按第一个释放者属性变化的终结技，演示中是风属性的终结技；
  - 终结技之后显示连锁的总伤害；
  - 演示中这一击把首领打进破防。

### 4.6 结算画面

- **内容**：
  - 「任务完成」和通关时间；
  - 综合评价，从 C、B、A、S 到 S+；
  - 每名队员的贡献数值，贡献最高的队员获得 MVP；
  - 经验增长与升级；
  - 奖励宝箱：铜、银、金宝箱依次打开，掉出的道具按稀有度区分；
  - 底部选项：再来一次、返回。
- **交互与动效**：评价的揭晓；各项数值依次出现；宝箱的打开，金宝箱的演出最隆重；可以按键跳过演出，直接显示全部结果。

### 4.7 剧情画面

- **对话框**：
  - 说话人的名字和对话文字，文字逐字出现；
  - 「自动」「快进」两个按钮；
  - 世界观名词，比如「天渊兽」「空行者」，在文字中标出，悬停或点击时弹出名词解释。
- **章节标题卡**：新章节开始时，全屏显示章节编号和章节名。
- **交互与动效**：说话人的切换；章节标题卡的出现与转场。

## 5. 交互演示

- 作品是一个可以操作的界面原型：
  - 用鼠标和键盘就能完成所有操作；
  - 每个可交互的元素都有悬停、按下和选中等状态；
  - 按游戏流程从一个界面走到下一个界面，返回键可以退回上一层。
- 战斗画面是一段可以操作的界面模拟：
  - 生命、奥义槽、连携值、模式槽、伤害数字按设计好的节奏变化，看起来像一场正在进行的战斗；
  - 观看者可以按键使用技能和奥义，界面给出对应的反馈；
  - 不操作时，战斗也会按一段编排好的流程自动推进：首领登场 → 交战 → 连携时刻 → 首领超载 → 连锁奥义 → 破防 → 讨伐成功，进入结算。
- 提供一个小巧的界面目录，可以直接跳到第 4 节的任意一个界面，方便逐个查看。进入视频导出模式后，不显示目录。
- 界面要适应不同大小的窗口，保持 16:9 的画面比例等比缩放。

## 6. 视频导出

作品提供以下接口，用于逐帧导出视频：

```js
window.videoExport.runs                          // ['tour']
await window.videoExport.begin('tour', { fps })  // 回到这一段的起点，返回 { frames }，即总秒数 × fps
await window.videoExport.frame(i)                // 显示作品时刻 i / fps 的画面，画好后返回
window.videoExport.end()                         // 回到正常的可操作状态
```

`tour` 是一段界面演示录像，内置在作品里，总时长一分半左右。录像按游戏流程依次展示第 4 节的全部界面，用一个可见的光标或选中框模拟玩家的操作，每一步都能看到界面的反馈和动效。

各部分的大致安排如下，顺序和时长可以调整：
- 标题画面：标志入场，展开主选单，选择「继续游戏」。
- 剧情画面：一段对话，点开一个名词解释；之后是章节标题卡。
- 任务柜台：切换难度档，选中「熔炉之巅的咆哮」，看详情。
- 编队与角色养成：换一名角色；打开艾琳的详情，更换一个技能和一枚徽印，看属性预览的变化；按下「出击」。
- 战斗画面：完整播放第 5 节的编排流程，包括连锁奥义的全部演出。这一段最长，约占整段录像的四成。
- 结算画面：评价揭晓，经验增长，宝箱依次打开。

录像的编排和操作由你完成，导出时直接调用 `tour`，不另外编排。

- fps 取 3（预览）或 60（正式）。导出模式下，作品时间只由 `frame(i)` 推进，结果不受机器快慢影响。
- 画面适应调用方设置的窗口大小，最高到 3840×2160。
- 以本地文件方式打开作品时，接口也要可用。

## 8. 交付与运行环境

1. 交付一个网页项目，入口文件为根目录下的 `index.html`，在 Chrome 中直接双击打开（以本地文件方式，不经过网页服务器）就能完整运行。注意：以本地文件方式打开时，Chrome 会拦截以文件引入的模块脚本、用 fetch 或 XHR 读取本地文件、从文件创建的 Worker，以及把图片文件用作 WebGL 纹理或读回其像素；普通 `<script src>` 和内联脚本不受影响。
2. 本机装有多种中英文字体，可以自行挑选合适的使用。
3. 本题只做 PC 端，不考虑手机和平板，用鼠标和键盘操作。
4. 环境接入了浏览器 MCP，使用无窗口的本机 Google Chrome 和显卡，可以随时用它打开、操作作品并截图检查。
5. 开发期间如需启动本地网页服务器，使用开场消息给出的端口。

## 9. 规定

1. 所有文件只在工作目录（本题面所在的文件夹）内读取、创建和修改，不访问其他路径；运行编译器、解释器、库、浏览器等必需工具时必须访问的安装路径和临时目录除外。截图等临时文件放在临时目录。
2. 全程独立作答，不开启子代理（subagent），不使用任何多代理或并行协作功能。
3. 不使用 `runas`，以及任何以其他账户身份登录、需要输入账户密码的命令。需要结束进程时，只按 PID 结束你自己启动的进程，不按进程名批量结束（`taskkill /IM`、`pkill`、`killall`、`Stop-Process -Name` 等）。
