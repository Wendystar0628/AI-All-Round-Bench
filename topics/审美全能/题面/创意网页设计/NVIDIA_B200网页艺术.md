# NVIDIA B200 网页艺术

## 1. 目标总览

以 NVIDIA B200 数据中心 GPU 为题材，制作一件可滚动、可交互的网页艺术作品。

这是一道主动性扩张的审美设计题：你是这件作品的设计者。题面给出题材、要表现的内容和几条要求；作品的整体构思、美术方向、叙事结构、篇章的数量和顺序、交互方式和动态表现，都由你决定。请在题面内容的基础上主动扩张，补充你自己的构思、场景和效果，做出一件完整、有辨识度的作品。

它是一件给人观看的艺术作品，不是产品发布页，也不是技术讲解。作品的分量来自三维、平面设计和动态的视觉表现：统一、丰富、连贯，审美水准高。观众通过画面、形态和运动感受题材，而不是阅读数据和图表。需要的产品资料由你自行查阅，用来启发造型和画面。

作品的体量大致是：全页 6–9 个篇章，纵向滚动约 15–25 屏。第 2 节的内容和第 3.2 节的体量下限都要在作品中真实做出来。作答过程中反复对照本题面逐项检查和完善。

## 2. 要表现的内容

下面七块内容都要在作品中呈现，每块写的是画面要表现的对象和意象。如何分章、先讲哪块、哪块做重、用什么画面来表现，由你安排；几块可以合进同一个篇章，也可以加入你认为值得表现的其他内容。

所有画面都从同一件实物里长出来：每个篇章的主视觉都从 B200 的封装、晶粒、服务器、机柜这些模型出发，或者是它们的投影、展开、剖面和版图。比喻和抽象的手法可以用，但要看得出它是从实物变过去的，例如晶粒的版图在镜头前渐渐亮成夜间的城市；不另起一幅与芯片无关的画。

### 2.1 芯片与封装

- 一颗完整的 B200 封装：两颗计算晶粒并排拼成一颗 GPU，四周是 HBM3e 显存堆栈，下面是中介层与基板。它是作品开场的主角，可以拆开、剖开或推近，看出各层的上下关系和彼此之间的连接。
- 晶粒的版图化作平面设计：纹样、建筑平面、夜间的城市，或者其他你构思的图形。
- 两颗晶粒之间的接缝：数据跨过接缝流动，两颗晶粒作为一颗 GPU 工作。

### 2.2 走进计算单元

- 从整颗 GPU 一级级推进到成组的计算单元，再到更小的单元，观看的尺度连续变化。
- 一项任务被切成许多小块，分发到成千上万个计算单元上同时完成，用大规模的群体运动来表现。

### 2.3 数据的流动

- 数据从 HBM 堆栈出发，沿中介层上的走线流进晶粒，经过缓存到达计算单元，算完再流回去。这股光在封装模型上或它展开的版图上，沿着真实的结构流动，看得出来路和去向。
- 数据供不上时计算单元暗着空等，供得上时成片亮起满载运转，两种状态在晶粒上形成对比。

### 2.4 精度

- 用画面本身表现精度：作品里已有的一幅画面（例如晶粒、封装或它们的版图）随着位数减少一级级变粗，色阶断层，轮廓变成块面、网点或抖动纹理，最后只剩寥寥几种颜色，却仍然认得出画的是什么。
- 一组数值共用一个缩放因子，在很少的位数里保住细节：画面被分成小块，每块各自调整色阶，粗糙的画面重新变得清晰。

### 2.5 张量计算与一次 AI 推理

- 张量核心里的矩阵乘加画成纵横交织的图形，例如织机上的经纬线，或者光栅交叉出的几何图案；这些图形从推近后的计算单元里展开，再收回去。
- 一次 AI 推理：输入的一句话或一张图被拆开，穿过一层层运算，变成输出。

### 2.6 从一颗 GPU 到一座数据中心

- NVLink 把多颗 GPU 连成一个整体。
- 观看的尺度一级级拉远：单颗 GPU，八 GPU 的 HGX／DGX B200，Grace CPU 与 Blackwell GPU 组成的 GB200，由计算托盘、交换托盘和背板连线组成的 GB200 NVL72 整机柜，再到成排机柜组成的数据中心。用三维场景、等轴测插画或建筑感的阵列构图来表现，不画组成框图。
- 一项计算分到多颗 GPU 上各自完成，再沿链路汇总。
- 电力送进机柜，液冷把热量带走。

### 2.7 结尾

- 镜头从数据中心一路收回，回到开场的那颗芯片封装，首尾呼应。作品停在画面上结束，不放总结和说明文字。

## 3. 作品要求

### 3.1 整体

- 作品有一个贯穿始终的构思和统一的美术方向：全页用同一套配色、材质和线条语言，各篇章看得出属于同一件作品，不在某个篇章里突然换成另一种画风。
- 开场第一屏要有完整、抓人的构图。
- 观赏优先：全页不出现图表、表格、数轴、柱状图、规格读数和讲解面板，也不做调参数看结果的实验台。数字最多作为排版里的图形元素偶尔出现。每个篇章的文字只有标题和一两句话。
- 标题、正文和操作提示层次清楚；动态排版停稳后可读，文字不遮挡画面主体。
- 整页在本机 Chrome 中滚动和交互流畅。

### 3.2 体量下限

- 可以近看的实时三维模型至少三套，分别处在不同的尺度，例如芯片封装、服务器平台和机柜。
- 平面设计在统一的美术方向下展开，用在版图、纹样、剖面、排版和字形等处，与三维模型互为表里。
- 每个篇章都有主视觉（三维场景或大幅的动态图形），不只是文字。
- 至少三处交互，每处都在三维或平面画面上产生真实的变化。

### 3.3 画面的变化

- 篇章之间的变化来自镜头、尺度、构图、光影和节奏，不来自换画风；不反复套用同一种版式或同一种动效。
- 三维、平面设计和排版各自用在最能发挥的地方，并且相互配合：平面图形与三维内容的比例、位置和运动对得上。
- 三维模型旋转、推近或拆开时能看到新的形体和空间关系；平面图形里的路径、图案和字形本身参与变化，不只做装饰。
- 细节服务于画面：大形、层次、材质、光影和动态优先，细节放在镜头看得到、观感收益高的地方，不为看不出来的结构堆料。
- 画面和动作都在网页中实时实现，不用视频、位图序列或整段淡入淡出代替。

### 3.4 篇章之间的衔接

- 篇章之间有能认出来的承接物，连续地进入下一个篇章，让人看出刚才看到的东西如何进入下一个尺度或下一种表现；不先清空画面再出现下一章，也不只靠整屏叠化。
- 随滚动推进的过程，停止滚动就停在当前位置，反向滚动就沿原路回退。
- 提供章节导航和当前进度；导航跳转可以更快，但仍从当前画面自然进入目标篇章。

### 3.5 交互

- 交互是体验式的，例如拆开和装回模型、拖动剖切面、拉动观看的尺度、用光标照亮或扰动画面。
- 新的操作可以打断正在进行的动画，并从当前状态转向新目标；用户的选择在跨篇章和回退后保留。
- 章节导航和交互支持键盘操作，焦点可以辨认。

### 3.6 主动扩张

- 在要表现的内容之外，至少加入两处你自己构思的内容或效果，例如一个贯穿全页的视觉隐喻、一段原创的场景、一种新的交互或叙事方式。
- 在交付目录根部的 `README.md` 里写明这几处是什么；页面上不放这类说明。

### 3.7 声明

- 在页脚或角落用一行小字注明“本页为概念设计作品，非 NVIDIA 官方页面”。

## 4. 网页艺术手法参考

下面是一些网页艺术中的高级手法，可以从中选用，不要求全部使用，也可以用清单以外的做法；选用的手法都服从作品统一的美术方向：

- 滚动驱动的镜头运动、分段钉住与视差分层，让滚动成为叙事的节拍。
- 三维与平面之间的形态转换：三维结构投影、展开成对齐的线稿或版图，或者反过来由线稿生长成三维。
- 海报式的构图：巨大的字形与大面积留白、瑞士网格排版、构成主义的斜向构图。
- 印刷与像素的语言：版画、网点、抖动、色调分离，用来表现画面的粗细与层次。
- 纹样与线描：从电路和版图里生长出的装饰纹样、等距的细线描绘。
- 等轴测插画与建筑平面：把服务器、机柜和机房画成精密的立体插图或平面图。
- 动态字形：字形拆成路径或粒子再重组，可变字体的字重、字宽随滚动变化。
- 着色器材质：薄膜干涉、各向异性金属、半透明与次表面效果，掠射角下的反光变化。
- 由场景深度决定的景深、与运动方向对应的运动模糊、只作用于亮部的辉光，以及色差、颗粒等后期处理。
- 实例化渲染与 GPU 粒子：成千上万的晶体管、数据块或光点同时运动。
- 剖切平面与实心截面、线框到实体的渐进构建、部件爆炸视图。
- 渲染到纹理形成的画中画、透过局部观察窗看到另一层结构的放大或折射。
- 程序化生成：按规则生成晶粒版图、走线、机柜阵列。
- 带惯性和弹簧阻尼的拖拽、可拆可装的部件、光标附近的照明与磁吸。
- 遮罩与裁切揭示、缩放穿越式的转场，从一个尺度推进到另一个尺度。

## 5. 视频导出

作品提供以下接口，用于逐帧导出视频：

```js
window.videoExport.runs                          // ['page']
await window.videoExport.begin('page', { fps })  // 回到开场状态，返回 { frames }，即总秒数 × fps
await window.videoExport.frame(i)                // 显示作品时刻 i / fps 的画面，画好后返回
window.videoExport.end()                         // 回到正常的可操作状态
```

`page` 是一段从页首到页尾的整页展示，包含文字、SVG、模型、导航和控件。页面从开头到结尾一直在滚动，中途不停顿。滚动的速度和节奏由你设计：可以随篇章的内容变快、变慢，让每个篇章的画面和动效都被看清。总时长不超过 70 秒，在这个范围内由你决定。

导出时直接调用 `page`，不另外安排滚动。

- fps 取 3（预览）或 60（正式）。导出模式下，作品时间只由 `frame(i)` 推进，结果不受机器快慢影响。
- 画面适应调用方设置的窗口大小，最高到 3840×2160。
- 以本地文件方式打开作品时，接口也要可用。

## 6. 交付与运行环境

1. 交付一个网页项目，入口文件为根目录下的 `index.html`，在 Chrome 中直接双击打开（以本地文件方式，不经过网页服务器）就能完整运行。注意：以本地文件方式打开时，Chrome 会拦截以文件引入的模块脚本、用 fetch 或 XHR 读取本地文件、从文件创建的 Worker，以及把图片文件用作 WebGL 纹理或读回其像素；普通 `<script src>` 和内联脚本不受影响。
2. 本机装有多种中英文字体，可以自行挑选合适的使用。
3. 本题只做 PC 端，不考虑手机和平板。
4. 环境接入了浏览器 MCP，使用无窗口的本机 Google Chrome 和显卡，可以随时用它打开、操作作品并截图检查。
5. 开发期间如需启动本地网页服务器，使用开场消息给出的端口。

## 7. 规定

1. 所有文件只在工作目录（本题面所在的文件夹）内读取、创建和修改，不访问其他路径；运行编译器、解释器、库、浏览器等必需工具时必须访问的安装路径和临时目录除外。截图等临时文件放在临时目录。
2. 全程独立作答，不开启子代理（subagent），不使用任何多代理或并行协作功能。
3. 不使用 `runas`，以及任何以其他账户身份登录、需要输入账户密码的命令。需要结束进程时，只按 PID 结束你自己启动的进程，不按进程名批量结束（`taskkill /IM`、`pkill`、`killall`、`Stop-Process -Name` 等）。
