## 简介

- **是什么**：给 AI 编程智能体做的限时测评平台。题目按专题组织，每个专题是一套独立的测评，有自己的题面、时长规则、评法、网页和片子。
- **测谁**：模型连同它自己的智能体工具一起测，例如 Claude Code、Codex。各专题的参测型号、所用智能体和推理强度登记在专题目录的 `参测.json`。
- **怎么测**：每题开一个新会话，在隔离的环境里独立作答。没有人回答问题，到时直接中止，作答目录里留下的就是提交。
- **怎么评**：由专题定。打分专题用程序校验和 AI 评分员给分，按权重合成总分并排行；展示专题不打分，只展示各模型的作品。
- **网站**：总站 [octathlon.wendystars.com](https://octathlon.wendystars.com) 列出各专题，每个上线的专题在 `/<专题标识>/` 下有自己的网页。

## 通用测试形式

下面是所有专题共用的机制。每道题的时长、交付物和作答资源写在专题清单 `专题/<专题名>/专题.json`，叫回语和提醒由专题配置；专题特有的安排见各专题自述。

### 谁在运转测评

| 角色 | 是什么 | 做什么 |
|---|---|---|
| 宿主 | 每个受测会话一个常驻进程 | 启动智能体，发开场提示，送达提醒，一轮结束后按时长规则叫回或交卷，到时中止；到时后保留，只由指挥关闭 |
| 监督进程 | 一个不含 AI 的常驻进程 | 每 2 秒巡检截止和提醒时刻，到时兜底，派发评分；把到时、失败、评分全部结束和新出现的异常通知指挥 |
| 指挥会话 | 一个 AI 会话，按操作手册行事 | 收到通知才行动：准备作答目录，逐批启动，处理故障和续做，归档已结束的会话日志，最后汇报；一个指挥统一调度所有专题 |
| 评分员 | 打分专题的 AI 评分员 | 按专题的评分指南打分；由谁来评、怎么评见各专题自述 |

### 一场作答怎样进行

| 项目 | 做法 |
|---|---|
| 会话 | 每道题开一个新会话，Job、核心保护和 Agent 初始化就绪后开始计时 |
| 时间信息 | 题面、开场提示、续做提示和提醒都不写限时和剩余时间 |
| 开场提示 | 说明题面位置、工作目录、交付物、工作目录中的内容即最终提交和结束进程的规则，并说明无人答疑、格式从宽；专题可以按题组另加说明 |
| 端口 | 需要本地网页服务器或调试端口的题，由平台给每个会话分配专用端口，写在开场提示里；题面不写死端口，几个模型同时答同一道题也不会冲突 |
| 答疑 | 除了系统故障说明，宿主只发专题配置好的固定消息 |
| 保存进度 | 所有题只以作答结束时工作目录中的内容为准，请及时保存成果 |
| 到时结束 | 管理员直接结束本项 Job，宿主、Agent、命令、服务器和浏览器一并退出；作答目录里留下的就是提交，会话保存在磁盘供续做 |
| 关闭与归档 | close 按管理员登记的 holder PID 和创建时间结束本项 Job；clean 结束已到时 Job 并归档日志 |

### 叫回、提醒与交卷

每道题都有最长时长，可以另设最短时长（专题清单的 `minutes`、`min_minutes`）：

| 时长规则 | 一轮正常结束时 | 怎样结束 |
|---|---|---|
| 只有最长时长 | 剩余超过 1 分钟就在几秒内发起下一轮（立即续做）；最后 1 分钟不再续做，会话空闲到时 | 到时中止 |
| 另设最短时长 | 累计作答未满最短时长时，每轮结束都叫回继续；满了之后，一轮正常结束即交卷 | 交卷，或到最长时长强制结束 |

- **叫回语和提醒：** 续做时发的话、半程的整体进度提示发给哪些题和在什么时刻，都由专题配置。
- **怎样送达：** 会话在运行时，提醒在模型下一次调用工具时插入（Claude Code 经钩子，Codex 经 `turn/steer`）；会话空闲时，宿主用它发起新的一轮。
- **不报时间：** 所有消息都不含具体时间。
- **连续空转：** 只有最长时长的题，连续 3 次续做都没有调用工具时，宿主不再续做，会话空闲到时；提醒照常送达。

<details>
<summary><b>提醒的去重与补发</b></summary>

- 每种提醒每段只发一次；整体进度提示按整题累计用时计算，续做时已发过的不重发。
- 中断期间漏发的整体进度提示，在续做开始时补发；续做段一开始就不多于 10 分钟的不补发。
- 同时积压几条定时提醒时，只送最新的一条。

</details>

### 故障与续做

| 情况 | 处理 |
|---|---|
| API 错误、额度用尽、宿主崩溃 | 关闭该会话，剩余时间 = 本段限时 − 已用时间，向上取整到分钟；用剩余时间接回原会话，不从头重测 |
| 接回后的第一条消息 | 说明会话因系统故障中断、此前进度已保留，并重申开场的规则，不报剩余时间 |
| 接不回原会话 | 在原作答目录开新会话，告知系统故障和已有进度（告知工作目录） |
| 同一题第三次故障 | 不再续时，记为“异常（已续时）” |
| 到时之后的故障、到时兜底强制结束 | 不续时 |
| 有独占整机的题正在作答 | 等那一批到时并清理后再续，不打破独占 |
| 启动失败 | 排查后再启动一次；第二次仍失败，记为启动失败 |

### 隔离的作答环境

- **账户：** 受测会话用一个专用的普通 Windows 账户运行，不在管理员组。题库仓库对这个账户整体拒绝访问，包括题面原件、评分资料和测评程序。
- **作答目录：** 按专题、型号、题分开；开场只复制本题题面和材料，不建立 Git 仓库。
- **会话之间：** 每个会话是这个账户的一次单独登录，会话进程的权限收紧到这次登录，会话之间不能结束彼此的进程。
- **作业对象：** 每个会话的全部进程放在一个 Windows 作业对象里。到时一并结束子进程。
- **智能体权限：** 智能体不开沙箱和审批（Claude Code 用 `bypassPermissions`，Codex 用 `approvalPolicy=never`），能做什么由账户权限决定。
- **记忆：** 每轮开测前，受测账户里智能体的记忆都已清空，作答时关闭自动记忆。会话日志在会话关闭后移到受测账户读不到的位置。
- **浏览器 MCP：** 受测会话接入同一个浏览器 MCP（chrome-devtools-mcp），用本机无窗口 Chrome 和显卡，每次使用独立的临时用户数据目录。
- **机器：** 作答和评分都在同一台机器上：Windows 11，Intel Core i7-14700KF（8 个性能核 + 12 个能效核，28 个逻辑处理器），NVIDIA GeForce RTX 4080（16 GB），64 GB 内存。
- **进程：** 进程生命周期统一由 `process_job.py` 管理：一项工作一个匿名、不可继承的 Windows Job，结束工作就结束 Job。受测会话和 bench 共用 session-host 与管理员 session_owner；评分、派工、发布用同一底层 runner；导出在同一底层上安装原有 CPU、内存和亲和性限制。只结束登记身份或已持有的本次子进程对象，不按账户、名称、目录或进程树扫尾。

### 所有题共同的规定

各题面的“规定”一节都写明下面三条；其余工具、联网和作品要求以各题面为准。

- 全程独立作答，不开启子代理，不使用任何多代理或并行协作功能。
- 只在工作目录内读取、创建和修改文件，不访问其他路径；编译器、解释器、浏览器等必需工具要访问的安装路径和临时目录除外。
- 不换账户登录（`runas` 等）；需要结束进程时只按 PID 结束自己启动的进程，不按进程名批量结束。

### 机器资源与并行

- **批次：** 专题把题分成批次作答；同一型号在同一专题里的不同批次不同时作答。不同专题之间只受机器资源限制。
- **占机：** 声明独占整机的题作答期间，不启动别的作答；声明需要安静机器的题作答期间，不评分。
- **评分：** 最多 16 个主体评分会话同时进行；性能评分一次一个，独占机器。

```text
├─ 平台/
│  ├─ 型号.json        全平台共用的型号身份

├─ 专题/<专题名>/        每个专题一份
│  ├─ 专题.json        专题清单：标识、类别、题组、评法，以及各题的时长、交付物和作答资源
│  ├─ README.md  README.en.md   专题自述
│  ├─ 参测.json        参测型号与所用智能体、推理强度
│  ├─ 题面/<类别>/<题名>.md   题面；同名文件夹放交给受测模型的公开材料
│  ├─ 评分/            打分专题才有：评分指南、评分表、参考答案、隐藏数据和评测脚本
│  ├─ 设计/            专题的设计系统，网页、片子、封面和自述配图共用
│  └─ 专题/十项全能/assets/readme/   自述配图（其他专题同样放在本专题目录下）
├─ website/
│  ├─ hub/             总站，在网站根路径
│  ├─ topics/<标识>/    各专题的站点项目，挂在 /<标识>/
│  └─ tools/           导出与发布
└─ archives/<标识>/     核心归档：按型号保存提交物、评分结果和开销
```

- 专题目录用中文名，网址、归档和本机数据用英文的专题标识（见[专题一览](#专题一览)）。
- 运行测评的调度程序、受测模型的作答目录和片子工程都在测试机本地，不在本仓库中。
- 新加一个专题只加它自己的目录和配置：专题清单、自述、参测登记和题面（打分专题另加评分材料）；要上站、出片时再加站点项目和片子模板。平台代码不动。

## 通用原则

### 出题

- **题面写做什么，不写怎么做**：题面交代主题、内容和要求；算法、库和代码结构留给模型。明显更合适的技术直接写成要求；运行环境里的坑照实提醒。
- **按强模型的读法写题面**：只写设计意图和作品的具体内容。能推出来的数值、系统做对了自然会有的结果、描述主观感受的词都不写；次要的内容一两句话带过。
- **难度靠实测校准**：不信 AI 对用时和难度的估计，要估难度就让模型实际做一遍。

### 作答

- **题面平实，不施压**：题面和注入的提示只写普通说明，不写“能力竞赛”“与其他模型比较”之类的话。打分专题的零分和扣分条款只写在评分指南里，题面只告诉模型评分对提交格式很宽容。
- **独立作答，用满时间**：没有人答疑；模型提前结束一轮时，宿主按时长规则马上叫回。
